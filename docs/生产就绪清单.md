# 生产就绪清单（可验收门槛）

> 目的：把「必须生产可用、必须安全稳定」翻译成能勾选的条目。
> 规则：**每条都有验收方式**；没验收方式的条目不算数；未全部通过前，版本号只能是 `0.x`。
> 最后核对：2026-11-15（v0.2.19：S-9 / T-4 / T-8 / O-4 转 ✅）。
> 功能面此后已到 v0.2.35（交互动作、消息层、图片下载、输入状态等），但 S/T 条目没有随版本逐条重跑；
> 下面的 ✅/⚠️ 以当时实测为准，恢复功能不等于重新验收生产项。
> 状态只有三种：✅ 已通过（附实测方式）、⬜ 未做、➖ 已放弃（写明原因）。
> 本次复查的完整问题与证据见 [复查报告-2026-11-15.md](复查报告-2026-11-15.md)。

## S · 安全

| 编号 | 要求 | 验收方式 | 状态 |
| --- | --- | --- | --- |
| S-1 | 业务进程不以 root 运行 | `ps -o uid,args` 看子进程 uid ≠ 0 | ⬜ **需要真机**：模块已能刷（[安装-Magisk.md](安装-Magisk.md)），但降权没验过；当前 proot 无 root，谈不上 |
| S-2 | 密钥只存 `secrets/`（0600），日志与 git 不含明文 | `doctor.sh` 查权限；`git log -p` 扫 token | ✅ `doctor.sh` 会报 600 与不合法权限 |
| S-3 | 业务端口只绑回环，对外的只有控制台 | 端口表 + `doctor.sh` 端口项 | ✅ 3001/6700/3080 均 `127.0.0.1` |
| S-4 | 运行时来源可验证（node 带 sha256，安装时校验） | `magisk-provision.sh --tarball` 不带 `.sha256` 必须拒绝 | ⚠️ 已做一半：rootfs 包强制校验、非空 rootfs 拒绝覆盖、`unit.sh explain` 可查实际路径；模块**仍不带 node**，装 node/dsh 由人在 rootfs 里做。真机未验，见 [ADR-0005](adr/0005-magisk形态与chroot.md) |
| S-5 | 入站消息当不可信：长度上限、类型白名单、拒绝路径穿越 | 构造异常输入必须被拒 | ⚠️ 部分：有 2MB body 上限、消息段类型白名单、图片 URL 的 SSRF/类型/大小校验；没有完整协议 fuzz |
| S-6 | 出站有硬上限（单条 4000 字） | 单测覆盖边界 | ✅ `bridge.mjs` 里 `slice(0,4000)`，自测覆盖 |
| S-7 | 日志脱敏 + 轮转 | 注入假 token 的日志里找不到原文 | ⚠️ `supervisor.log` 过 `redact()`；桥接器/网关错误摘要自行脱敏；NapCat 自己的日志不保证。supervisor 与单元日志在启动时按 `LOG_MAX_MB` 轮转一次，长跑期间不切 |
| S-8 | 失败关闭：配置缺失不启动 | 删 token 启动必须非 0 | ✅ 网关 `WEB_TOKEN` 为空直接退出 78；`run-bridge.sh` 缺 node/入口返回 78。验：`WEB_TOKEN= node units/web/gateway.mjs` |
| S-9 | 依赖锁定 + 审计 | `bin/check-deps.sh` 通过；故意加一个裸模块名 import 必须失败 | ✅ 本仓库零第三方依赖：门禁只允许 `node:` 内置与相对路径，出现 `node_modules`/`dependencies` 即失败；`doctor.sh`「资源与依赖」实跑通过；新增依赖须先写 ADR |
| S-10 | 线上文件只能经 git 改动 | 部署只做 checkout | ⚠️ `/opt` 下的 launcher 与 OneBot 配置不在 git；已用脚本（`napcat-start-host.sh`、`napcat-wire-onebot.sh`）保证可重放 |
