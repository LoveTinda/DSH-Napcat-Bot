# 生产就绪清单（可验收门槛）

> 目的：把“必须生产可用、必须安全稳定”翻译成能勾选的条目。
> 规则：**每条都有验收方式**；没验收方式的条目不算数；未全部通过前，版本号只能是 `0.x`。

## S · 安全（Security）

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| S-1 | 业务进程**不以 root 运行**，降权到普通应用 uid；root 只留在 supervisor | `ps -o pid,user,args` 看子进程 uid ≠ 0 |
| S-2 | 密钥只存 `secrets/`（0600），日志、git 历史、QQ 输出都不含明文 | `grep -R` 扫日志与 `git log -p`，正则找 token；命中即不合格 |
| S-3 | 只监听 Unix socket（0600），**不开 TCP**；连接校验 peer uid | `ss -xl` 无监听端口；`stat` socket 权限 600 |
| S-4 | 运行时来源可验证：node 二进制带 sha256，安装时校验 | `customize.sh` 校验失败即 abort |
| S-5 | 入站消息一律当不可信：长度上限、类型白名单、`@文件` 限制在工作区内、防路径穿越 | 构造 `@../../data/...` 用例必须被拒 |
| S-6 | 出站有硬上限：单条 4000 字 / 6 条气泡 / 图片 ≤10MB / 视频 ≤20MB；抓图拒绝私网地址（SSRF） | 单测覆盖边界值 |
| S-7 | 日志脱敏（token/手机号/Bearer）+ 按天轮转 + 只写 `/data/adb` | 注入假 token 的测试日志里找不到原文 |
| S-8 | 失败关闭：策略未命中 = 拒绝；密钥缺失 = 不启动 | 删掉 token 启动，必须退出非 0 |
| S-9 | 依赖锁定 + 定期审计（`npm audit`） | `package-lock.json` 入库；audit 无 high |
| S-10 | 线上文件只能经 git 改动，禁止热补丁直接改 | 部署脚本只做 checkout + 校验和 |

## T · 稳定（Stability）

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| T-1 | 崩溃退避重启 + 熔断（10 次 / 5 分钟放弃） | 杀进程 3 次观察退避与日志 |
| T-2 | 优雅停止：SIGTERM → 5 秒 → SIGKILL；退出前把状态落盘 | `supervisor.sh stop` 后 state 完整 |
| T-3 | 状态**原子写**（tmp + fsync + rename），断电不留半截 JSON | 写入中途 kill -9，重启能读 |
| T-4 | 资源上限：heap 512MB、fd 1024、core 0 | `ulimit -a` 与 `NODE_OPTIONS` 核对 |
| T-5 | 磁盘配额：日志 50MB 轮转；state 体积上限；超限告警 | 灌日志到 60MB，观察轮转 |
| T-6 | 健康检查：每 30 秒探活 socket + 事件循环延迟；连续 3 次失败视为不健康 | `state/health.json` 有 lastOk 时间戳 |
| T-7 | 启动顺序：等 `sys.boot_completed` + 20 秒；上游（NapCat）未就绪时重连而不是退出 | 断开 NapCat 启动，进程仍在且日志有重连 |
| T-8 | 断网/断线：outbox 补发 + 消息 id 去重（幂等） | 断网发 5 条，恢复后不重不漏 |
| T-9 | 升级可回滚：模块目录版本化 + git revert，10 分钟内回退 | 演练一次回滚 |
| T-10 | 压力基线：1000 条消息/小时不 OOM、无句柄泄漏 | 压测脚本跑 1 小时，RSS 平稳 |

## O · 运维（Operations）

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| O-1 | 一键排障：`bin/doctor.sh` 输出 环境/进程/socket/最近错误 | 跑一遍能定位常见故障 |
| O-2 | 日志按 turn / session 可检索 | `grep 'turn: 123'` 能串起来一轮 |
| O-3 | 备份验证：每天自动 push；离线 bundle；**每次更新写一份完整目录到 `/sdcard/backup`**；每周恢复演练 | 备份目录存在且 `SHA256SUMS` 校验通过；从备份能直接跑起来 |
| O-4 | 告警：连续失败、磁盘 >80%、推送失败 → 通知到 QQ | 手工触发一次能看到通知 |
| O-5 | Runbook：列出 10 种故障的处置步骤 | `docs/runbook.md` 存在且每条可执行 |

## Q · 质量与流程

| 编号 | 要求 |
| --- | --- |
| Q-1 | 单测覆盖：命令解析、权限矩阵、`/output` 四档渲染矩阵、策略命中 |
| Q-2 | 提交前门禁：`node --check`、单测、文档同步检查 |
| Q-3 | 每次发版有 CHANGELOG 条目与 git tag |
| Q-4 | 改动前必须有快照（`bin/snapshot.sh`），纳入门禁 |
