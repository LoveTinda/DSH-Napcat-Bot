# 接口与本地适配

> 目的：让“能分享的通用接口”和“只适合这台机器的优化”物理隔离，且接口永远和代码对得上。

## 三分法

| 类别 | 位置 | 入 git | 规则 |
| --- | --- | --- | --- |
| **契约** | `contracts/*.contract.json` | 是 | 机器可读；改它等于破坏性变更 |
| **通用实现** | `app/src/` | 是 | 只能实现契约，不得私加方法 |
| **本地优化** | `local/` | **否** | 只能实现契约，不得改契约；文件头写 `// overrides: <id>` |

## 四条硬规则

1. **先契约后实现**：新增一个外部边界（新传输、新模型、新存储），先写 `contracts/x.contract.json`，再写实现。没有契约的实现一律不合入。
2. **契约只增不改**：真要改签名，升 `version`，并在同一提交改完所有实现与测试；旧版本实现要么迁移要么删除。
3. **优化不上传**：设备特化、账号特化、反检测相关的改动只放 `local/`；`local/**` 在 `.gitignore` 里。上传前跑 `git status --ignored` 自查。
4. **一致性检查进门槛**：`bin/check-contracts.sh` 验证「契约声明的方法 ⊆ 实现导出的方法」；实现多出来的方法必须回到契约里登记，否则视为漂移。

## 加载顺序

```
内置实现（app/src/*.js）
  → local/ 同名覆盖（local/<id>-*.js）
  → 运行时注入
```

`local/` 覆盖在启动日志里必须打印一行：`loaded local override: <file> (contract=<id>)`，保证“我到底跑了哪份代码”可查。

## 为什么这么定

- 通用接口入库 → 换设备、换账号、开源、给别人用都不受阻
- 优化不入库 → 设备特化不会污染通用层，也不会因泄露暴露本机特征
- 一致性检查 → 防止“实现偷偷长成事实标准”，那是最难还的债
