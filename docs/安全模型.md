# 安全模型

> 目的：说清楚“防谁、防什么、防不住什么”。不写这一节，安全就会变成拍脑袋。

## 资产
1. QQ 账号（NapCat 登录态）——最高价值，泄露 = 账号被接管
2. DeepSeek API key / DSH token
3. 项目源码与对话记录（隐私 + 商业价值）
4. 设备本身（root）

## 威胁者
| 威胁者 | 能力 | 主要防线 |
| --- | --- | --- |
| QQ 里的陌生人 / 群成员 | 发任意消息、图片、@、文件引用 | 策略默认拒绝、命令需权限、入站当不可信、@文件限定工作区 |
| 本机其他 App | 读取共享存储、探测端口 | 业务端口一律 `127.0.0.1`；对外只有 8443 一个 HTTPS 口且要 token；secrets 0600 |
| 拿到设备的物理接触者 | 解锁后可用 root | 状态与密钥 0600、日志脱敏、可远程吊销 token |
| 供应链 | 恶意 npm 包 / 篡改的 node 二进制 | 依赖锁定、运行时 sha256 校验、不执行模型给的依赖安装 |
| 模型输出本身 | 可能包含恶意指令 | 模型输出只当文本发出去；涉及执行必须走受控工具与白名单 |

## 关键控制
1. **最小权限**：supervisor 是 root，业务进程降到应用 uid（S-1）
2. **最小暴露**：控制台以外全部只监听回环；无关端口一个不开（见下表）。桥接面板和
   OneBot 入口共用 6700，面板**只读**，不提供配置写入/会话删除接口
3. **失败关闭**：策略未命中拒绝；网关 `WEB_TOKEN` 为空时拒绝启动（除非本机调试显式
   `WEB_ALLOW_NO_TOKEN=1`）；桥接器监听非回环时 `doctor.sh` 直接 FAIL
4. **不可信输入**：长度/类型白名单；路径拼接后必须仍在工作区内（realpath 前缀校验）
5. **供应链**：零第三方依赖，`check-deps` 只放行 `node:` 内置与相对路径；出现
   `node_modules` / `dependencies` 即提交失败（S-9）
6. **发不出去也不丢**：回复进入 `state/bridge/outbox.json`（0600、最多 100 条、按 TTL 过期），
   不写日志、不显示在面板正文；告警同样只发一条私聊，不落盘
7. **不可追溯即不合格**：改动必进 git，会话转录入库
8. **图片下载是唯一新增出站请求面**：只允许 http/https；默认拒绝 localhost、私网、
   链路本地、多播；域名先解析再逐地址检查；手动跟 3xx，每一跳重新校验；只收
   png/jpeg/gif/webp；10MB/8 张/8s 默认上限；落盘 0600、目录 0700
   （`BRIDGE_IMAGE_ALLOW_PRIVATE_HOSTS=1` 会削弱这条防线，只给内网 NapCat 用；
   决策见 [ADR-0006](adr/0006-图片落盘与SSRF.md)）
9. **开机只自启 web，业务进程只在 proot 里**：`service.sh` 只建目录/补配置/写日志，再 fork
   后台 `bin/boot-start.sh` 立即退出（等开机、起单元都不占开机阶段）；默认 `AUTO_START=web`，
   `off` 回到零动作。`web` 与 `bridge` 都是 `TYPE=proot`：宿主 root 域只跑 supervisor，
   业务 node 在 DSH App 的 proot 里，未 bind 的目录不可见；探测不到就 78
   （决策见 [ADR-0008](adr/0008-启动与挂载安全.md) 与 [ADR-0012](adr/0012-业务进程只跑proot.md)）

## 残余风险（明确接受）
- **ACE 可能识别 root**：本设计不注入进程，但 root 本身可能被识别；已确认 `/data/adb/modules` 存在不触发封禁
- **root 域进程被攻破 = 全设备失守**：因此业务降权，supervisor 只做生命周期管理
- **QQ 账号被盗**：无法在设备侧完全防住，只能限制其权限（不给 owner）
- **日志里可能残留敏感片段**：脱敏是正则，不是保证
- **补发队列里有回复正文**：`outbox.json` 是 0600 且送达/过期即删，但断网期间
  root 可读；不介意这一点才把长回答留在队列里，介意就调小 `BRIDGE_OUTBOX_TTL_MS`
- **落盘图片会留在 state 里**：没有自动清理，只有 0600 权限；模型能读，root 也能读。
  介意就定期清 `$DATA/state/bridge/images`，或设 `BRIDGE_DOWNLOAD_IMAGES=0`
- **DNS 与 fetch 之间有 TOCTOU**：校验时解析到公网、请求时重新解析到内网仍可能发生；
  已用「解析结果检查 + 每跳重定向校验」降低概率，但没有绑定 IP 的 dispatcher
- **chroot 传播回退**：真机 `unshare -m` 可用，但 toybox 不认
  `mount --make-rprivate`；`bin/make-private.sh` 会试 `-o rprivate` 等写法，
  并要求 `mountinfo` 全树无 `shared:`。toybox 的 `-o rprivate` 实际是 slave，
  不是严格 private；安全性依赖「无 shared、不回传宿主」。不支持时自动退回 exec，
  显式 chroot 失败关闭。业务进程仍以 root 运行，chroot 不是降权

## 复审
每次新增外部输入面（新命令、新传输方式、新文件类型）都要回来更新本文件。

## 当前传输面（2026-11-15 实测）

| 端口 | 绑定 | 谁能连 | 鉴权 |
| --- | --- | --- | --- |
| 3001 | `127.0.0.1` | 只有本机桥接器 | `Authorization: Bearer secrets/napcat.token` |
| 6099 | `::`（NapCat 默认） | 本机；对外不可达 | WebUI 自己的 token（`webui.json`） |
| 6700 | `127.0.0.1` | 本机 NapCat + 本机浏览器 | 依赖回环绑定；面板只读；**不接受外部事件** |
| 8443 | `0.0.0.0` | 局域网 | 控制台 token → **HttpOnly** cookie `tinda`；`?k=` 只用于首次进入，页面加载后从地址栏抹掉 |
| 8444 / 8445 | `0.0.0.0` | 局域网 | 同一枚 HttpOnly cookie；没有 token 直接 401 |
| 3080 | `127.0.0.1` | 只有本机 | DSH 自己的启动 token（网关代签不了，见 RUNBOOK.md §7） |

早期设计是「只 Unix socket、不开 TCP」，实际落地改成了 TCP + token：
NapCat 的 OneBot 只支持 HTTP/WS，网关也只能用 HTTP 反代，socket 这条路走不通。
代价是必须保证回环绑定不被改掉——`doctor.sh` 的「暴露面」项会检查 `BRIDGE_LISTEN` 与
`NAPCAT_API` 的主机部分，非回环直接 FAIL 或 warn。

2026-11-15 复查补充：
- 网关 cookie 改为 HttpOnly 后，桥接面板/NapCat 页面里的脚本读不到控制台 token；
  网关转发给下游时会先去掉 `tinda` cookie，避免把控制台 token 顺带交给 NapCat。
- 导航页不再把 token 拼进 iframe URL；`?k=` 在首次 HTML 加载时由网关注入 cookie，
  页面脚本用 `history.replaceState` 清掉地址栏里的 `k`，减少历史记录与 Referer 泄露。
- 桥接面板的失败备注会先脱敏再截断；聊天正文从不进入面板快照。
- `WEB_HTTP_PORT` 明文逃生口仍存在；打开它等于让 token 走明文，只在证书装不进信任库时临时用。

## 模型输出的边界

模型可能的输出只当文本回发到 QQ，**不执行**。桥接器不做任何命令解释、不把模型输出当 shell 输入。
