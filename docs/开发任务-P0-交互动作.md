## 1. 要做的事

新增 `units/bridge/interactions.mjs`，让模型能在正文里写标记，桥接器执行后把标记从可见文本里删掉。
旧版就是这么干的（`bridge.js:1198-1255` 的 `emit()`），调用点还在，实现丢了。

### 1.1 三个标记

| 标记 | 动作 | OneBot 调用 |
| --- | --- | --- |
| `[[react:赞]]` `[[react:爱心]]` … 或 `[[react:123]]`（数字表情 ID） | 给**用户那条消息**加表情回应 | `set_msg_emoji_like` `{message_id, emoji_id}`（emoji_id 用字符串；中文名走内置映射：赞/爱心/笑哭/鼓掌/疑问/捂脸） |
| `[[recall]]` | 撤回**本轮已发出的所有气泡** | `delete_msg` `{message_id}`，逐条删 |
| `[[poke]]` | 戳一戳发消息的人（群里戳群成员） | 私聊 `friend_poke` `{user_id}`；群 `group_poke` `{group_id, user_id}` |

### 1.2 硬性规则（旧版踩过的坑，别重犯）

1. **代码围栏里的标记不执行**：正文先按 ``` 切段，只在围栏外解析
2. **纯动作、无可见正文时不发空消息**（否则 QQ 里出现一条空白）
3. **每轮最多 2 个动作**，多余的丢掉并在日志里记一行 `忽略多余动作`
4. **动作有总时限 2500ms**，超时/失败都**不阻塞正文**：正文照发，只记 `warn: 动作执行异常`
5. **撤回是"删本轮气泡"**，所以必须等气泡都发完再执行；实现上：先收集 `message_id`（`sendReply` 现在没返回 id，要改成返回 `data.message_id`）
6. 群里 `group_poke` 默认关（`behavior.interactions.groupPoke:false` 的等价键），避免绕过 mention 策略

### 1.3 提示注入（告诉模型有这些标记）

- 每个 **DSH 会话只注入一次**，别每轮都拼（旧版为此烧过 token，见 `bridge.js:436` 注释）
- 注入点：`askDsh()` 拼 prompt 的地方，标记「本会话已注入过」（内存 Set 即可，进程重启后重注一次无害）
- 文案要短，讲清：能写什么、会被删掉、最多 2 个、代码块里不生效

## 2. 配置（四件齐：代码校验 + 面板字段 + 文档 + 变更记录）

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `BRIDGE_INTERACTIONS` | 1 | 总开关，0 = 不解析也不执行（正文里的标记原样保留） |
| `BRIDGE_INTERACTIONS_GROUP_POKE` | 0 | 群里允许 `[[poke]]` |
| `BRIDGE_INTERACTIONS_MAX` | 2 | 每轮最多几个动作（1–5） |
| `BRIDGE_INTERACTIONS_TIMEOUT_MS` | 2500 | 动作总时限 |

面板 `units/bridge/panel.mjs` 加一行「交互动作」：开关 + 本轮执行了几个 / 失败几个（**不记正文**）。

## 3. 测试（必须两个文件）

`units/bridge/test-interactions.mjs`（纯函数，≥14 条）：
- 解析：单个/多个标记、`[[react:数字]]`、未知动作、空标记、大小写
- 围栏内不解析、围栏跨多行、未闭合围栏
- 超过上限只保留前 N 个
- 中文表情名映射；未知名字当 ID 原样传
- 删掉标记后正文的空白处理（不留双空行、不 trim 掉段落）

`units/bridge/test-interactions-wire.mjs`（真起桥接器 + 假 NapCat，≥10 条）：
- 私聊：`[[react:赞]]` 发出 `set_msg_emoji_like`，且用户看到的消息里**没有** `[[`
- `[[recall]]` 删除本轮气泡（假 NapCat 记 `delete_msg` 的 message_id，要与发送时返回的 id 一致）
- 群聊：`[[poke]]` 在默认配置下**不**发 `group_poke`；打开配置后发
- 纯动作回复：不发空消息，但动作执行了
- 动作 API 报错：正文照样送达，日志里有 warn
- `BRIDGE_INTERACTIONS=0`：标记原样进正文、不发任何动作请求

参考现成写法：`units/bridge/test-typing-wire.mjs`（假 NapCat 记录请求 + echo 后端）。

## 4. 交付流程（顺序别乱）

1. `sh bin/snapshot.sh 交互动作改造前`
2. 写代码 + 测试；`node --check` 每个改过的文件

4. 全套测试：`for t in units/bridge/test-*.mjs units/web/test-*.mjs; do node "$t" || echo FAIL $t; done`
5. 文档：`docs/配置说明.md` 新增小节（§4.10 交互动作）、`docs/待恢复清单.md` 把 1–8 划掉、`CHANGELOG.md` 新版本、`module.prop` +1

7. `git add -A && git commit`（格式见 AGENTS §5：标题 + 为什么/影响/验证），`git push origin main`
8. 汇报：改了什么、测试多少条通过、哪些是推断（没有旧源码的部分必须说明）
