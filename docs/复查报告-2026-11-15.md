# v0.2.18 全量复查报告

> 复查对象：`tinda-bot` 仓库（提交 `fadb559`，模块版本 `v0.2.18`）
> 复查时间：2026-11-15
> 复查方式：逐文件阅读 + 三道门禁 + 4 套自测 + 线上接口实测 + 进程/日志核对
> 结论：**主要链路已通，Bridge 面板与网关的已知硬伤已修；契约仍未实现，属于 0.x 的已知缺口。**

## 0. 一句话结论

这次不是“UI 换个皮”，而是把 **Bridge 面板打不开/手机上看不了、网关空 token 放行、token 进 iframe URL、
restart 留下旧进程占端口、旧配置永远读不到、快照漏掉代码** 这几类会直接导致“看起来在跑、实际不可信”的问题
逐条修掉了；同时把“哪些没做”如实写回文档，避免再用告警冒充通过。

## 3. Bridge 面板专项

### 3.1 之前到底坏在哪

最硬的一个：面板页在 `/panel/` 下把“当前目录”当成挂载点，取状态时拼成
`/panel/panel/state.json`——这个地址不存在，所以页面能打开、数字永远不动。
测试只断言了 HTML 里有 `panel/state.json`，没有真的从 `/panel/` 发一次轮询，所以没抓到。

第二个：网关把导航页 iframe 指向 `/bridge/`，页面里的相对路径在“带前缀”和“不带前缀”两种情况下
解析结果不同；旧实现只覆盖了其中一种。

第三个：手机视口。6 列 `white-space: nowrap` 的表格在 390px 宽度下必然溢出，
而页面又没有横向滚动容器；配置页直接 `JSON.stringify` 一大坨，既不可读也没有“这是只读”的提示。

### 3.2 现在怎么工作

- 页面固定用相对地址 `state.json`，所以：
  - `/panel/` → `/panel/state.json`
  - `/` → `/state.json`
  - `/bridge/` → `/bridge/state.json`（网关转发到桥接器 `/state.json`）
- 桥接器同时提供 `/state.json` 与 `/panel/state.json`，兼容旧书签和 doctor。
- `GET /` 固定返回面板 HTML；`GET /healthz` 固定返回 JSON；不再靠 `Accept` 猜。
- 会话/事件改成卡片列表；配置按“连接/行为/DSH/其它”分组，只读展示。
- 轮询 2 秒；页面隐藏时暂停；可手动刷新 / 暂停自动刷新；失败显示错误条和排查命令。
- 事件支持“全部/成功/失败/跳过”筛选；会话 id 可一键复制。
- 详见 [Bridge面板.md](Bridge面板.md)。

### 3.3 仍然刻意不做

- 不提供写配置、删会话、重启桥接器按钮。面板和 OneBot 入口共用 127.0.0.1:6700，
  本机任意进程都能直连；加写接口等于给本机任意进程一个“改配置/重启”的后门。
- 不显示聊天正文。事件只存 chatKey、耗时、状态、字数/错误摘要（脱敏后截断）。
- 不做“像素级”浏览器回归（本机没有浏览器）；已做 HTML/路由/接口测试，移动端布局需要人眼再看一次。

## 4. 网关专项

- 空 token 拒绝启动（`exit 78`）；只有显式 `WEB_ALLOW_NO_TOKEN=1` 才允许空 token。
- `?k=<token>` 首次进入时种 **HttpOnly** cookie；页面脚本不再读取 token；地址栏里的 `k` 由
  `history.replaceState` 抹掉。
- 转发给下游前会去掉 `tinda` cookie，保留下游自己的 cookie（NapCat WebUI 登录态）。
- `/bridge`、`/dsh`、`/napcat` 无斜杠时 308 到带斜杠；`/logout` 清 cookie。
- DSH 401 只在请求 `Accept` 含 `text/html` 时换成说明页；API 请求原样透传。
- 下游错误返回 502 + HTML/文本说明，不再让 iframe 一片空白。
- 端口与鉴权流程详见 [网关.md](网关.md)。

## 5. 桥接器专项

- OneBot 事件先回 204，再进该聊天的串行队列；同一 chat 不并发。
- `classifyEvent` 把事件分为“要处理”和“跳过 + 原因”；消息类跳过会写一条 skip 事件。
- DSH 失效会话：正则匹配 `unknown/not found/no such/不存在/未知`，清映射、重开一次并记 skip。
- DSH 输出保留尾部 4MB，stderr 保留尾部 4000 字符；超时 SIGKILL。
- stdin 加 `error` 处理；DSH 提前退出不再把 EPIPE 变成未捕获异常。
- 失败摘要先 `redactText` 再写事件/日志/回发；不记录聊天正文。
- SIGTERM 时给正在跑的 DSH 子进程发 TERM，1.5 秒后还在的 KILL；避免 `unit.sh stop` 留孤儿。

## 6. 配置与运维专项

### 6.1 配置补齐

`ensure_dirs` 在首次运行/每次启动时会用 `etc/tinda.conf.example` 给缺的键补默认值：

- 不覆盖已有值
- 不删旧键（旧键由 doctor 报“未知配置键”）
- 只补合法键名（字母/数字/下划线）
- 保持 `0600`

### 6.2 死键与推导

删除了 `BRIDGE_PANEL_PORT` 配置键。桥接面板没有独立端口，它和桥接器共用 `BRIDGE_LISTEN`；
`run-web.sh` 从 `BRIDGE_LISTEN` 推导出网关内部变量 `BRIDGE_PANEL_PORT`，改监听端口只需改一处。

### 6.3 token 与证书

- `secrets/web.token` 缺失或为空 → 生成 16 字节（32 位十六进制），原子替换，0600。
- 证书 SAN 至少包含回环 + `WEB_LAN_IP`；启动时用 `openssl x509 -checkend` 和 SAN 检查，
  不覆盖当前 IP 或 24 小时内过期就重签；旧文件保留为 `.old`。
- `WEB_HTTP_PORT` 真正 export 给网关；默认 0，不开明文。

### 6.4 单元与进程

- `unit.sh stop` 不再只认 PID 文件：按命令行找 `unit.sh start/restart <name>`、
  `units/<name>/...`、`bin/run-<name>.sh`，收集整棵 `/proc/.../children` 再杀。
- 跳过“`cd … && sh unit.sh …`”这种包装命令行，避免把调用者 shell 当单元进程。
- `start` 发现未登记进程会拒绝启动并提示先 stop，避免旧实例占端口时又起一个。
- 详见 [生命周期.md](生命周期.md) 的 PID 语义。

### 6.5 日志

- `supervisor.log` 每次写前按 `LOG_MAX_MB` 检查轮转。
- 单元日志在 `unit.sh start` 时检查一次；长跑期间不会自动切（文档已如实写）。
- 桥接器/网关错误摘要自行脱敏；NapCat 自己的日志不保证脱敏。

## 9. 残余风险与未完成

1. **契约未实现**：`dsh/model/onebot/store` 四个契约仍是目标形态；`check-contracts` 只是告警。
   1.0 前必须补齐或重写，不能继续用警告冒充门禁。
2. **没有浏览器像素回归**：本机无浏览器；移动端布局按 390px 设计并做 HTML/接口测试，
   建议在手机浏览器实开一次。
3. **单元日志轮转不完整**：长跑进程不会自己切；需要外部定时任务或改成 pipe + 轮转。
4. **NapCat 日志不脱敏**：它自己的输出，模块不接管；敏感排查时注意。
5. **DSH 面板仍不可代理**：它只认启动时打印的授权串，这是设计，不是 bug。
6. **旧配置键**：`.runtime/etc/tinda.conf` 仍有 13 个重写前的键；代码不读，doctor 会告警，
   按清单手工清理，不要整份覆盖。
7. **没有推送 GitHub**：只做了本地提交与 `/sdcard/backup` 备份。
