# ADR-0017：桥接面板端口按「认面板」探测跟随

- 状态：已采纳
- 日期：2026-11-20
- 相关：ADR-0003（web 入口）、ADR-0012（业务进程只跑 proot）、ADR-0016（token 以文件为准）

## 背景

控制台上「桥接器」永远是红的，点开只有「这个面板还没起来」。真机上实测：桥接器活着
（`6702` 面板 200、`/state.json` 200），但网关把 `/bridge/` 代理到 **`6700`**——那是
OneBot 事件入口，forward-ws 模式下没有任何进程监听。

两处问题：

1. `bin/run-web.sh` 用 `BRIDGE_LISTEN`（`127.0.0.1:6700`）推导 `BRIDGE_PANEL_PORT`。
   `BRIDGE_LISTEN` 是 OneBot 入口，不是面板；文档里「面板与 OneBot 共用 6700」是 v0.2.x 的形态。
2. 端口顺延（`bin/port-fix.mjs`）没有跟随者。上一轮的残留实例占着 6701/6702 时，
   新实例顺延到 6703/6704，网关仍盯 6702。而回收残留实例的 `reap_port` 依赖
   `/proc/net/tcp`——Android 上它只列出「与读进程同 uid」的 socket，业务进程跑在应用 uid，
   宿主 root 也看不见，所以「按端口回收」在真机上是哑的，实例一轮攒一个。

## 可选方案

### A. 什么都不做，改文档让人手改端口

- 成本最低，但每顺延一次就要人肉发现、人肉改配置，正是这三十轮的形状。不采用。

### B. 桥接器把生效端口写进共享文件，网关读文件

- 语义最干净（单一真相），和 ADR-0016「token 以文件为准」同构。
- 但宿主与 proot 的 `/data` **实测是两份内容**（`/data/adb/tinda-bot/state/app` 的 mtime
  停在 11-19），能同时被两侧写到的只有 `/sdcard`；把运行期契约放到不可信、可被别的应用
  写的共享存储上，等于用一个新的可靠性问题换掉旧问题。不采用。

### C. 网关在本机回环上「认面板」探测（采用）

- 候选：`BRIDGE_PANEL_PORT`（默认 6702）+ 6700–6710；判据不是「端口通了」，而是
  `GET /` 返回 200 且页面里有「桥接器面板」——6701 是 admin 口（回 JSON），不会被认错。
- **只在配置端口没人监听时才扫**：端口上有响应（哪怕是别的服务）就保持不动。否则配置写错会被
  悄悄盖成「另一个能用的下游」，坏得更难查。
- 5 秒节流、在途去重、启动先探一次；只在当前端口认不出时才扫，稳定期每 5 秒一次本机 GET。
- 端口变化写一行日志（`[web] 桥接面板端口跟随：a → b`），事后能对齐。
- 同时修根因：`unit.sh` 增加 `reap_unit_procs`，按 `TINDA_NAME` 环境变量认人回收残留实例，
  不再依赖那条在真机上哑掉的 `/proc/net/tcp` 路径。

### D. 给桥接面板单开一个「根路径」端口（像 DSH 8444 / NapCat 8445）

- 面板是自包含单页（无绝对路径资源，`base = new URL('state.json', location.href)`），
  挂在 `/bridge/` 前缀下能正常工作；多开一个对外端口只是多一份暴露面。不采用。

## 决定

采用 C：面板端口以「探测到的实例」为准，配置值只是候选起点；实例回收改用环境变量认人。
新增配置键 `BRIDGE_PANEL_PORT`（默认 6702），四件齐：`bin/run-web.sh` 校验、`/module/` 页
`bridgePanel` 字段（配置值 + 实际值）、`docs/配置说明.md` 一行、`CHANGELOG.md` 一条。

## 代价与残余风险

- 探测有猜的成分：如果 6700–6710 上出现了「页面里也写着桥接器面板」的第三方服务，会认错。
  当前端口范围只归本模块用，风险接受。
- 两个实例并存时取「先命中」的那个，可能拿到旧实例的面板。数据来自同一份 `status.json`，
  观感差异很小；真正的解法是 `reap_unit_procs` 让旧实例死掉——它失败时日志里有痕迹。
- `reap_unit_procs` 依赖 `/proc/<pid>/environ` 可读（root 可读应用 uid 的 environ）；
  读不到就跳过，只会退化成「不杀」，不会误杀。

## 何时该重审

- 真机上出现 `reap_unit_procs` 回收失败（日志里「命令行不认识」或根本没日志）时；
- 桥接器改成固定端口 + 启动即失败（不再顺延）时，本 ADR 的探测部分可整体删掉；
- 有别的服务也占用 6700–6710 时，候选范围必须收紧。
