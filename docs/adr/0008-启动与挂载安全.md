# 0008 启动与 chroot 挂载安全

## 背景

v0.2.35 模块刷入后出现开机卡很久、系统服务/应用起不来的事故。审计启动链发现
[service.sh](../service.sh) 会等 `sys.boot_completed` 最多 180 秒，再 `sleep 20`，
然后一次性拉起 napcat/dsh/bridge/web；[unit.sh](../bin/unit.sh) 的 `spawn_chroot()`
会把 `/data/adb` bind 进 `/data/adb/tinda-bot/rootfs/data/adb`——源目录是目标的祖先，
形成递归挂载；而且没有 unmount、没有私有 mount namespace，挂载会留到重启。
另外 napcat 是 `TYPE=auto`，rootfs 存在时会被塞进 chroot 跑 Android QQ，必然失败重试。

## 可选方案

1. **什么都不做**：保留开机自动拉起和旧挂载。功能最全，但已经证明会拖垮开机。
2. **彻底删掉 chroot，只留宿主直装**：风险最低，但 rootfs 里的 DSH/node 用不上，
   等于放弃模块的主要价值。
3. **保留 chroot，但改成私有 namespace + 最小挂载，并默认不自动启动（选中）**：
   需要 chroot 的人手动启动；namespace 退出即销毁挂载；不再 bind `/data/adb`；
   napcat 永远宿主直装。

## 决定

选 3：

- `service.sh` 只建目录/补配置/写日志，**不启动任何单元**，不等 boot_completed、不 chroot；
  服务由人手动 `unit.sh start`。
- `unit.sh` 的 chroot 只在该环境 `unshare -m` + namespace id 校验 + 传播探针通过时启用；
  否则 `auto` 退回 `exec`，显式 `chroot` 失败关闭。（v0.2.37 起传播探针改为
  `bin/make-private.sh`，兼容 toybox 不认 `--make-rprivate` 的情况。）
- 在私有 mount namespace 里只挂：`/proc`、`/dev`（nosuid,noexec）、`/sys`
  （ro,nosuid,nodev,noexec）、模块代码（ro）、`etc/state/logs/run/secrets` 五个状态目录；
  **不挂 `/data/adb`，不挂 `/sdcard`**。
- 用符号链接让宿主路径 `/data/adb/modules/tinda-bot`、`/data/adb/tinda-bot`
  在 chroot 里可解析，不再靠 bind 祖先目录。
- `napcat/unit.conf` 固定 `TYPE=exec`，Android QQ 不进 glibc rootfs。
- 失败关闭：mount/权限/符号链接冲突都 `exit 78`，namespace 销毁，不在宿主留挂载。

## 代价与残余风险

- 默认不自动启动，刷完不会自己跑服务；要手动起，和“开机自启”的旧预期不同。
- chroot 依赖 `unshare` 和私有传播；不支持的设备自动退回宿主直装，可能缺 rootfs 内的 node/DSH。
- 不挂 `/sdcard` 后，rootfs 内看不到共享存储；桥接/web 不需要，但手工进 chroot 的人要另挂。
- v0.2.37 真机确认 namespace 隔离可用，但 toybox 不认 `mount --make-rprivate`；
  已改为多写法回退，并要求 `mountinfo` 全树无 `shared:` 才继续。toybox 的
  `-o rprivate` 实际是 slave，不是严格 private；安全性依赖「无 shared、不回传宿主」。
  bind/remount 与回退写法仍要在目标机型上验证。
- 业务进程仍以 root 运行（S-1 未通过），chroot 不是降权。

## 2026-11-18 真机修订

v0.2.36 在真机上 `unshare -m` 成功、namespace id 变了，但 `mount --make-rprivate`
失败。toybox 的 mount 不支持 util-linux 的 `--make-*` 语法；它的 `-o rprivate`
又被映射成 `MS_SLAVE|MS_REC`（slave，不是 private）。

因此增加 `bin/make-private.sh`：依次尝试 `--make-rprivate`、`-o remount,rprivate`、
`-o rprivate`、`-o remount,private`、`-o private`；每一步后用
`/proc/self/mountinfo` 检查全树没有 `shared:`，才允许继续挂载。`unit.sh` 同时校验
子进程 namespace id，删除了原来单层 `--make-private` 回退。toybox 回退到 slave 时
日志会写 warn；这是「不回传宿主」的次优解，不是严格的 private 语义。

## 何时重审

- 真机验证 `mount | grep tinda` 干净、开机无延迟后；
- 需要恢复开机自启时（应做成显式 opt-in，并加 watchdog/超时）；
- `unshare` 在目标机型不可用时；
- 要把 chroot 业务降权、或改成真正容器时。
