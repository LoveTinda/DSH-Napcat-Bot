# AGENTS.md —— 项目规范（人和 AI 都按这份来）

> 放在仓库根、叫 `AGENTS.md`，是因为这是现行的通用约定：AI 编码工具会先读它，
> 人也知道规范在哪。内容就是原来的 `AGENTS.md`，没有换一套要求。

> 这份规范的目的：**任何人（包括三个月后的你）拿到代码，不用问人就能知道它为什么存在、怎么改、改坏了怎么退回去。**
> 本项目上一次的事故代价是两个月的工作，所以这里每一条都有明确的“为什么”，不是形式主义。

> 配套：`RUNBOOK.md`（怎么起、怎么查、怎么修）、`docs/生产就绪清单.md`（S/T/O/Q 四组，逐条有验收方式）。
> 未全部通过的版本只能是 `0.x`。

## 0. 三条铁律

1. **先备份，再改**：动任何原文件之前，先跑 `bin/snapshot.sh`，产出 `originals/<时间戳>/`。`originals/` 是只读的，任何人不得修改或删除（`chattr +i` 可选）。
2. **没有“目的”的代码不合入**：每个文件、每个导出函数，必须有“目的”段落。写不出目的，说明这段代码不该存在。
3. **配置项必须四件齐**：代码校验 + 面板字段 + 文档章节 + 变更记录各一行。缺一件视为未完成。
   面板只读展示也算「面板字段」，但字段必须出现；不能把配置藏在只有 SSH 才能看到的文件里。

## 0.5 接口与本地优化必须分离

契约进 `contracts/`（入 git），设备/账号特化进 `local/`（**不入 git**），两边的边界见 `docs/接口与适配.md`。
提交前必须跑 `bin/check-contracts.sh` 与 `bin/check-deps.sh`。

依赖只有一种允许的形态：`node:` 内置模块 + 相对路径。要加第三方依赖必须先写 ADR，
并同时改 `bin/check-deps.mjs` 的白名单——不能为了"先跑起来"绕开门禁。

## 0.6 每次更新必须落地一份完整备份

发版/大改后**必须**执行 `bin/backup-to-sdcard.sh`，产出 `/sdcard/backup/tinda-bot-<版本>-<时间>/` 完整目录（含 `.git`、`originals/`），并登记 `INDEX.md` 与 `SHA256SUMS`。

为什么：本机被清空过一次，共享存储是唯一“即使设备挂着也还能捞”的位置。

## 1. 文件头注释（强制）

每个源码文件开头必须包含：

```js
/**
 * 目的：这份文件解决什么问题，谁在用。
 * 边界：它不做什么（避免后来人往里塞不该有的职责）。
 * 依赖：依赖谁、被谁依赖、外部进程/端口/文件。
 * 失败：出错时会发生什么（抛错/降级/退出），调用方该怎么处理。
 */
```

**为什么**：这一层是“接手成本”的主要来源。事故后重建时，最先缺的就是“这段代码为什么这么写”。

## 2. 函数注释（强制，导出函数 100%）

```js
/**
 * 目的：做一件什么事（一句话，动词开头）。
 * 输入：参数含义、合法范围、缺省行为。
 * 输出：返回什么、可能为空时是什么。
 * 失败：可能抛什么、什么条件下降级、是否重试。
 * 副作用：写文件/发网络请求/改全局状态（没有就写“无”）。
 */
```

**为什么**：桥接器一半的 bug 来自“以为它不会抛错”和“以为它没有副作用”。

## 3. 设计文档（ADR）

任何影响行为的重大决定，写一份 `docs/adr/NNNN-标题.md`：

```
背景 → 可选方案（≥2，含“什么都不做”）→ 决定 → 代价与残余风险 → 何时该重审
```

已有 ADR：
- `0001-不用注入用 init 服务.md`
- `0002-git 全量可追溯.md`（已被 0004 取代）
- `0003-web入口与https.md`
- `0004-仓库内git与手动提交.md`
- `0005-magisk形态与chroot.md`
- `0006-图片落盘与SSRF.md`
- `0007-群消息层默认值.md`
- `0008-启动与挂载安全.md`
- `0009-单应用合并.md`
- `0010-proot启动.md`

**为什么**：这次 `/output` 四档差点永久丢失，就是因为“为什么这么设计”只存在于聊天记录里。

## 4. 目录与命名

| 位置 | 内容 | 规则 |
| --- | --- | --- |
| `app/` | 唯一的桥接应用（原版会话/工作区/面板 + 当前安全层） | 只放能跑的代码；不 import units/ |
| `units/` | 外围单元（napcat / web / dsh）与 bridge 的 unit.conf | 只放能跑的代码；单元之间不互相 import |
| `bin/` | 模块自身的可执行脚本 | Android sh，禁 bashism |
| `etc/` | 配置模板 | `.example` 结尾，真配置不入库 |
| `docs/` | 规范、架构、ADR、命令表规格 | 变更必须同提交 |
| `originals/` | **只读**原文件快照 | 永不修改 |
| `/data/adb/tinda-bot/` | 运行态：state/logs/secrets/repo | 不入模块目录 |

命名：文件 `kebab-case`，变量 `camelCase`，常量 `UPPER_SNAKE`，命令 `动词-宾语`。

## 5. 提交规范

```
<类型>(<范围>): <一句话结论>

为什么：<动机，不写“改了什么”>
影响：<配置/行为/兼容性>
验证：<跑了什么测试>
```

类型：`feat` `fix` `refactor` `docs` `test` `chore`。
**一个可运行单元一个提交**；不允许“顺手修一下”混在大提交里。

**为什么**：`git log` 就是审计链，`git bisect` 就是回退工具。message 写“为什么”，diff 本身已经说明了“改了什么”。

## 6. 原文件备份（机制，不是口号）

```sh
bin/snapshot.sh <原因>
# → originals/20261115-0300-<原因>/
#    + originals/INDEX.md 追加一行（时间、原因、文件数、哈希）
```

- 每次大改、迁移、批量重写之前必须跑
- 快照里保留**原始字节**，不做格式化、不做重命名
- `INDEX.md` 记录每条快照的 sha256，用来证明确实是原件

**为什么**：这次能捞回 10-25 的代码，靠的是一份“当时没人觉得重要”的 tar 包。备份机制存在，运气才有意义。

## 7. 测试

- 每个命令至少一个“参数解析 + 权限”用例，一个“正常路径”用例
- 渲染类（如 `/output` 四档）必须有“档位 × 内容类型”的矩阵用例
- 改配置解析，必须补一条“非法值拒绝”的用例

## 8. 禁止事项

- 静默 `catch {}`：至少 `log.warn` 一条带上下文的日志
- 魔法数：阈值必须具名，并写清“为什么是这个数”
- 往 `/sdcard` 写可执行文件或放代码（会被全局扫描，且共享存储不可信）
- 模块进程注入别的进程（Zygisk/ptrace/LD_PRELOAD）——见 ADR-0001
- 对外监听非回环端口（例外：控制台 8443 必须对外，且必须带 token；此例外见 `docs/安全模型.md`）
- 改代码不改文档：门禁脚本会提示，但 `docs/`/`CHANGELOG.md` 是否同提交仍由人负责（pre-commit 不判断语义）

## 9. 文档同步检查（门禁）

可执行的门禁（`bin/install-hooks.sh` 能把前四项装成 pre-commit）：
1. 所有 `.js`/`.mjs` 过 `node --check`（有 node 时）
2. 所有源码文件头必须有 目的/边界/依赖/失败 四项（`check-headers.sh`）
3. 单元之间不得互相引用（`check-independence.sh`）；零第三方依赖（`check-deps.sh`）；
   契约与实现一致性（`check-contracts.sh`，当前如实告警）

仍需人工确认的：
4. 配置文件里的键，必须在 `docs/配置说明.md` 出现
5. 更新 `CHANGELOG.md`
6. 改 `units/**`/`bin/**` 时同提交改 `docs/**`

钩子不在 git 里，换机器要跑一次 `sh bin/install-hooks.sh`；没装时这几道要手动跑。
