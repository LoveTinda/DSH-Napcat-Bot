## 6. policy —— 访问策略与命令权限

一条规则 = 「什么条件（when）→ 放不放行（action）→ 给什么角色（role）→ 还能改什么（caps/model/inject）」。
规则**有序**，自上而下第一条命中即生效；都没命中走 `defaults`（默认 deny）。
`rules` 为空会**拒绝启动**。

### 6.1 规则字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 日志/`/policy` 里的名字 |
| `name` | 否 | 备注 |
| `when` | 是 | 条件对象，见 6.2 |
| `action` | 否 | `allow`（默认）/ `deny` |
| `role` | 否 | `owner` / `admin` / `user` / `none`，默认 `user` |
| `caps` | 否 | 只做授权：`allow` / `deny`，见 6.3 |
| `model` | 否 | 给这个聊天钉默认模型别名（**规则字段，不放 caps**） |
| `inject` | 否 | `false` 时不注入「对方/本群资料」 |
| `reason` | 否 | 拒绝原因（出现在事件与 `/status`） |
| `enabled` | 否 | `false` 临时停用 |

### 6.2 when 条件

| 键 | 说明 |
| --- | --- |
| `chat` | `private` / `group`（**必须写**，不写会被判成死规则） |
| `user` | 对方 QQ：glob（`*` `?`）、`!x` 取反、数组任一 |
| `group` | 群号，同上 |
| `self` | 机器人自己的 QQ |
| `mentioned` | 是否 @ 了机器人（群里只想接 @ 就写 `true`） |
| `text` | 原文 glob；复杂用 `{"re":"…"}` / `{"contains":"…"}` |
| `len` | 长度：`{"gte":20}` / `{"gt"}` / `{"lt"}` / `{"lte"}` |
| `time` | `"09:00-23:00"`（支持跨零点）或 `{"from":"22:00","to":"06:00"}` |
| `weekday` | `1-7`（周一=1）、`[1,2,3]`、`"mon-fri"` |
| `hour` / `minute` / `date` | 精确匹配 |

操作符：`re` `glob` `eq` `in` `contains` `prefix` `suffix` `gt` `gte` `lt` `lte` `from` `to` `not` `any` `all`。

### 6.3 caps：allow / deny（唯一授权机制）

- 值是**命令路径数组**，`deny` 优先于 `allow`，`allow` 优先于角色下限；
- 路径可以到**子命令**：`persona.add`、`sessions.all`、`session.bind`、`session.who`、
  `session.title`、`session.use`、`session.release`、`session.list.all`；
- 写父命令会连子命令一起管：`deny:["persona"]` 同时禁 `persona.add`；
- **新增命令不需要改权限系统**：在命令表里写一行 `minRole`（子命令写 `sub`）即可。

### 6.4 命令权限表（命令表就是唯一真相）

| 命令 | 最低角色 | 子命令（路径 → 角色） |
| --- | --- | --- |
| /help | user | — |
| /status | user | — |
| /ping | user | — |
| /new | user | — |
| /stop | user | — |
| /sessions | user | all → sessions.all (admin) |
| /session | user | use/switch/切换 → session.use (admin)；title/rename/改名/标题 → session.title (admin)；release/unbind/解绑/释放 → session.release (admin)；bind/接管/adopt → session.bind (admin)；who/归属 → session.who (admin) |
| /ws | admin | — |
| /ls | user | — |
| /model | admin | — |
| /effort | admin | — |
| /output | admin | — |
| /persona | user | add → persona.add (admin) |
| /balance | admin | — |
| /policy | user | — |
| /notice | user | — |
| /permission（DSH 命令） | owner | — |

> 例外：`/session list all` 在 handler 里用同一套 `capsAllow(..., 'session.list.all', 'admin')`。

### 6.4.1 访问控制（唯一的一套策略）

面板 `/config` →「访问策略」只有一份东西：

| 面板上写的 | 含义 |
| --- | --- |
| 白名单 + 名单 | **一个集合**：QQ 号、群号混填。关 = 所有人可用；开但名单空 = 不限制 |
| 管理员 QQ | 不受白名单限制；能改配置 / 管会话 / 接管会话 |
| 允许切 DSH 权限预设 | 勾上 = 主人；不勾 = 管理员。这是两者**唯一**区别 |
| 群里必须 @ 我 | 群里只有 @ / 回复才回 |
| 命令权限矩阵 | 每行一条命令 × 两列身份（白名单成员 / 管理员），三态：跟随身份 / 允许 / 禁止 |
| 兜底设置 | 没命中时怎么处理（默认拒绝）、忽略自己的消息 |

`policy.rules` 是**生成物**：保存时按 access 重算并写盘；加载时只要 `policy.access`
存在就按它重新生成（手改 rules 不会生效）。所以「高级」里只有只读预览，没有第二套模型。

想要按关键词 / 时间 / 单独拉黑这类规则，必须删掉 `policy.access` 再手写 `policy.rules`
（这时面板显示「规则表模式」）。

### 6.5 defaults / ignoreSelf

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `defaults.action` | `deny` | 没命中规则时的动作 |
| `defaults.role` | `none` | 没命中时的角色 |
| `defaults.reason` | `default-deny` | 拒绝原因 |
| `ignoreSelf` | `true` | 忽略机器人自己发的消息 |

### 6.6 常见写法

```json
{ "id":"主人", "when":{"chat":"private","user":"10001"}, "action":"allow", "role":"owner" }
{ "id":"群里@", "when":{"chat":"group","group":["777"],"mentioned":true}, "action":"allow", "role":"user",
  "caps":{"deny":["ws","model"]} }
{ "id":"放行建人设", "when":{"chat":"private","user":"10001"}, "action":"allow", "role":"user",
  "caps":{"allow":["persona.add"]} }

  "model":"flash", "inject":false }
```

| `aiDisclosure` | `true` | 首次进群发使用提示 |
| `groupContext.enabled` | `true` | 群聊把"最近消息"一起给模型（含没 @ 的）；已注入过的按时间水位去重，不会每轮重讲 |
| `groupContext.mode` | `related` | **注入哪些**（最终取哪几条）：`related` 按相关度取（用下面的打分器）/ `latest` 最新 n 条 / `first` 最早的 n 条（按时间补齐） |
| `groupContext.scanLimit` | `100` | 扫描多少条候选（1–200）；"只看最近 100 条"就靠它 |
| `groupContext.maxMessages` | `0` | 注入条数上限；**0 = 不按固定条数**，由相关度决定，只受 `limits.maxInject` 安全上限约束 |
| `groupContext.alwaysRecent` | `2` | 最近 N 条**必带**：保证"刚说完的话"不会因为不相关被漏掉 |
| `groupContext.minScore` | `0` | 相关度下限；低于它的候选不进（保底那几条不受限） |
| `groupContext.windowMs` | `1800000` | 回看窗口（默认 30 分钟） |
| `groupContext.maxChars` | `2000` | 注入块的字符上限；超过就自动压缩（先丢最早的整条，剩一条还超就截断），0 = 不限 |
| `groupContext.ranker` | `bm25` | **相关度怎么算**（只在 `mode=related` 时生效）：`bm25` 本地词法（零成本、确定性）/ `llm` 单次小请求让模型挑（默认 deepseek-flash，**关闭思考**）；`latest`/`first` 下这一项被忽略 |

两阶段：**打分器（ranker）**回答“哪几条算相关”，**注入哪些（mode）**回答“最后带哪几条”。`mode=related` 才走打分器；`latest`/`first` 直接按时间取，跟打分器无关。`scanLimit`/`windowMs` 是候选池范围，对三种 mode 都生效；`maxMessages`/`limits.maxInject` 是条数上限，也共用。

固定顺序：**候选（窗口内全部，含已发过的）→ 排序 → 排除已发过的 → 卡条数 → 按时间输出**。已发过的消息只用来帮打分器理解语境，不再重复发；`alwaysRecent` 保底只从未发过的里取最近 N 条。

| `groupContext.llm.apiKeyEnv` | `DEEPSEEK_API_KEY` | key 来源：环境变量 → `$DSH_HOME/.credentials.yaml` 的 refs（复用 DSH 自己的 key）|
| `groupContext.llm.timeoutMs` | `8000` | 超时就回落 BM25 |
| `groupContext.llm.maxCandidates` | `100` | 一次最多把多少条交给模型排 |
| `groupContext.llm.maxCandidates` | `100` | 一次最多把多少条交给模型排 |

### 7.6 catchUp —— 停机补收

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 上线后补处理停机期间的消息 |
| `windowMs` | `1800000` | 回看窗口（30 分钟，合法范围 60000–86400000） |
| `maxPerChat` / `maxTotal` | `3` / `10` | 每聊天 / 总共最多补几条（1–50 / 1–500；越界直接拒绝启动，不再静默夹到 5/20） |
| `historyCount` | `50` | 每个聊天向 NapCat 拉多少条历史再筛（10–200） |

补收只覆盖**最近聊过的聊天**（`lastInboundAt` 还在窗口内），且每条都要通过策略；
被策略拒绝的也会记水位，避免每次启动重放。补收进来的消息同样进「最近消息」缓冲，
所以重启后 @ 机器人时还能看到停机那几句（受上面条数限制）。

想直接确认缓冲里到底有什么、下一条会带哪几条：QQ 里发 `/context`（别名 `/上下文`、`/最近消息`）。

## 7.7 autoCompact —— 会话上下文自动压缩

- `behavior.autoCompact = { enabled, thresholdRatio, cooldownMs }`：每轮结束后读 DSH 的 `contextPressure`，
  占比 ≥ `thresholdRatio`（默认 0.8）就调一次 `/compact`，`cooldownMs`（默认 600000）内不重复压。
- 上限/冷却都可配；面板「配置 → 行为 → 自动压缩会话上下文」三连；`/status` 的「压缩」一行会显示
  阈值、冷却、以及当前上下文占比（超阈值时提示“本轮结束会压”）。

## 10. 人设 / 模式（DSH agent preset，不在 config.json）

- 一条人设 = 一个 DSH preset（`@deepseek-ai/dsh-agent-preset` + `@deepseek-ai/dsh-persona`），
  prompt 进**系统提示词**；桥接不再自己拼人设，也不保存名单。
- 列表每次现问 DSH：`GET /personas`（管理接口）或 QQ 里 `/persona`。
- `config.json` 里**没有** `persona` 段（桥接旧的人设模块已删除，历史配置已清理）。
- 新建：`POST /personas` `{"id","name","prompt"}`（要 admin token），或 `/persona add <id> <名字> | <提示词>`，
  或面板「配置 → 人设」。写入 `$DSH_HOME/profiles/web/cordis.patch.yml`；
  写完轮询 3 秒，没热加载会返回 `restartRequired:true`（重启 DSH）。
- 默认人设 = DSH 的 settings 字段 `agent-preset-registry.selectedDefault`（没设就回 registry 的 `default`，当前 `standard`）。
  面板「配置 → 人设 → 默认人设」或 `POST /api/presets/default`（要 panel token）可改；只影响之后新建的会话。
- 权限：列表所有人可看；新建要 admin。要放开给某个角色，在策略规则里写 `"caps":{"allow":["persona.add"]}`。
- **切换**：`/persona <id>`（例如 `/persona ptc`）。`agentPreset` 只能在建会话时指定，所以这条命令会
  1) 把 id 记到本聊天（`chat.agentPreset`，存 `sessions.json`），2) 开一条新会话（旧会话保留，`/ws` 可切回），
  3) 建完用 `projections.agentPreset` **核对**，DSH 没照做就回滚并明说，不假装成功。
  之后这个聊天的每次 `/new` 也带同一个人设。`/status` 的「人设」行显示本聊天指定值。
- **限制**：只有 `transport=api`（DSH 网页在跑）能切。headless 通路（`profiles/qq` 没有装
  `dsh-agent-preset` 插件，`dsh --profile qq` 的参数也只有 `--json/--session-id`）建会话时没有
  preset 入口，命令会直接说切不了，而不是回一段列表冒充成功。

## 11. 配置界面

- 面板：`http://127.0.0.1:6702/config`（写入口要 `panel.writeEnabled` + Bearer token）；顶部有**配置搜索**（按名称/路径/说明过滤，自动切到命中的分区）；

- 管理接口：`http://127.0.0.1:6701`（`state/admin.token`）；`GET /personas` 只读，`POST /personas` 要 token；
- 策略调试：`/policy 文本`、`GET /api/policy`、`POST /api/policy/check`。
