# 开发任务：P0-1b 撤回语义修正（`[[recall]]` 删上一轮，不是本轮）

> 上一轮任务（P0-1）交付里有一处**语义错位**：实现和提示词都写「撤回本轮气泡」，
> 结果模型想说「刚才答错了，正确的是 X。`[[recall]]`」时，正文先发出去、
> 紧接着又被自己删掉——用户看到一条错误答案闪一下消失，什么都没留下。
> 旧版（救回的 `bridge.js` 的 `emit()`）是**先动作、后发正文**，所以 recall 删的是**上一轮**。
> 这个修复就是把语义改回旧版。

## 1. 要做的事

### 1.1 记住「上一轮的气泡」

在 `bridge.mjs` 里按聊天键维护一份 `lastBubbles`：

| 点 | 行为 |
| --- | --- |
| 每轮正文发完（拿到 `messageIds`） | 把本轮 id 存成该聊天的「上一轮」 |
| 下一轮解析出 `[[recall]]` | 删**上一轮**存的 id，**不碰本轮** |
| 该聊天还没有上一轮（第一次对话 / 刚重启） | recall 记 `skipped`，日志 `warn: 没有上一轮气泡可撤回`，不报错 |
| 纯动作回复（只有 `[[recall]]`，没有正文） | 不发空消息；删掉上一轮后本轮结束 |

**内存即可，不用落盘**（气泡 id 只在 NapCat 会话有效期内可删，重启后陈旧 id 反而会报错）。
在文件头注释里写明这一点。

### 1.2 传给 `runActions` 的入参改名/加字段

现在的入参是 `{ info, messageIds }`，`messageIds` 被 recall 当成本轮。改成：

- `currentIds`：本轮刚发的（`react` 不用它，留着给将来）
- `prevIds`：**上一轮**的（`recall` 用这个）

`runActions` 里 recall 分支改成读 `prevIds`；`currentIds` 暂时只用于日志。

### 1.3 提示词改口

`interactionHint()` 里那句改成：

```
[[recall]] 撤回你上一轮发出的气泡（用于"上一句说错了，整段纠正"）；本轮正文不会被撤回。
```

不要再说「撤回本轮」。

### 1.4 执行顺序

保持 P0-1 的「先正文、后动作」——它保证动作慢/失败不挡正文，是对的。
只有一处例外要记住：**纯动作**时没有正文，直接执行动作。逻辑上已经是这样，别改回去。

## 2. 测试（必须改旧断言 + 加新用例）

### 2.1 改掉那条错的

`test-interactions-wire.mjs` 里「分条后逐条撤回」断言的是**本轮** id 被删 —— 那正是 bug。
改成两轮场景：

```
第 1 轮：发一条长回复 → 记下 2 条气泡 id
第 2 轮：发 "刚才说错了，正确的是 X。[[recall]]"
断言：
  - delete_msg 删的是第 1 轮的 2 个 id（顺序、数量都对）
  - 第 2 轮的气泡 id **没有**出现在 delete_msg 里
  - 第 2 轮正文正常送达（用户看得到 X）
```

### 2.2 新用例（≥6 条）

- 首次对话就 `[[recall]]` → 不发 `delete_msg`，日志有 warn，这一轮不失败
- 纯动作 `[[recall]]`（无正文）→ 不发空消息 + 删上一轮
- 上一轮是纯动作（没气泡）→ 本轮 recall `skipped`
- 连续三轮：第 2 轮 recall 删第 1 轮；第 3 轮 recall 删第 2 轮（不是第 1 轮）
- `BRIDGE_INTERACTIONS=0` 时标记原样保留、不发 `delete_msg`
- recall 的 `delete_msg` 失败（假 NapCat 返回错误）→ 正文仍送达、只记 warn
