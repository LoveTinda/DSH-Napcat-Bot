# ADR-0003：统一 Web 入口 + 自签 HTTPS

## 背景
需要从别的设备打开 DSH / 桥接面板 / NapCat WebUI；逐个开放端口既难记也难管。

## 可选方案
1. 各服务各自绑 0.0.0.0，分别记端口
2. 一个反代入口（/dsh/ /bridge/ /napcat/），统一鉴权
3. 只走 Tailscale / SSH 隧道，不开放端口

## 决定
选 2，同时保留 3 作为推荐用法。

## 理由
- 一个地址、一个 token，减少暴露面与心智负担
- 反代层能做统一 401、统一 502 提示，下游没起来不至于让人以为是“坏了”
- 自签证书解决“明文传输”的最低要求，但**不等于可信**：浏览器会警告

## 代价与残余风险
- 自签证书无法消除中间人风险，只是加密；公网使用必须上 Tailscale
- token 是唯一凭证，泄露即等于拿到执行权 → 必须可轮换（删 token 文件重启即可）
- 反代会掩盖下游的真实来源 IP，排障时需看反代日志

## 何时重审
获得域名并接入 Let's Encrypt，或决定全面走 Tailscale 时。
