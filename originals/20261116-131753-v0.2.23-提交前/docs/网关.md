# 网关：鉴权、反代和失败模式

> 目的：把 `units/web/gateway.mjs` 的行为写清楚：谁在听、token 怎么走、请求怎么转发、坏了是什么样。
> 边界：只做 HTTP 转发与鉴权；不解析业务；不缓存正文；不代签 DSH；不支持 WebSocket 升级。
> 依赖：`bin/run-web.sh` 准备 token/证书/端口；下游 DSH 3080、桥接面板 6700、NapCat 6099。
> 失败：配置缺失/空 token 拒绝启动；下游不可达 502；下游 401 按请求类型处理。

## 1. 拓扑与端口

```
浏览器
  │  https://<LAN IP>:8443/?k=<token>      控制台（导航页 + /bridge/ + /_/status）
  │  https://<LAN IP>:8444/                 DSH 根路径端口（绝对路径资源）
  │  https://<LAN IP>:8445/                 NapCat 根路径端口（/webui、/api）
  │  http://<LAN IP>:8088/                  明文 301 → 8443（可关）
  ▼
gateway.mjs
  ├─ 127.0.0.1:3080  DSH
  ├─ 127.0.0.1:6700  桥接器（OneBot 入口 + 只读面板）
  └─ 127.0.0.1:6099  NapCat WebUI
```

| 端口 | 谁在听 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| 8443 | 网关主入口 | token → HttpOnly cookie | 导航页不鉴权；`/_/status`、`/bridge/`、`/dsh/`、`/napcat/` 要鉴权 |
| 8444 | 网关 origin dsh | 同一 cookie | 根路径直接透传 `/dsh/`；否则 DSH 的 `/assets`、`/api` 会 404 |
| 8445 | 网关 origin napcat | 同一 cookie | 根路径直接透传 `/napcat/`；NapCat 页面 token 自动补 |
| 8088 | 网关明文跳转 | 无（只 301） | 不承载内容 |
| 6700 | 桥接器 | 无（回环） | 面板只读；OneBot POST |
| 6099 | NapCat | 它自己的 token | 只被 8445 反代 |
| 3080 | DSH | 它自己的授权串 | 网关不代签 |

## 2. 鉴权流程

### 2.1 首次进入

```
GET https://IP:8443/?k=<WEB_TOKEN>
  → 网关校验 token（常量时间比较）
  → Set-Cookie: tinda=<token>; Path=/; HttpOnly; SameSite=Lax; Secure
  → 返回导航页 HTML（不含 token）
  → 页面脚本 history.replaceState 去掉地址栏里的 k
```

### 2.2 后续请求

- 浏览器自动带 cookie；`authed()` 从 `Cookie` 头取 `tinda` 并做常量时间比较。
- `?k=` 仍可用于独立端口/书签的首次进入，但页面不会再把它拼进 iframe URL。
- `/logout` 返回 `Set-Cookie: tinda=; Max-Age=0` 并 302 到 `/`。

### 2.3 失败关闭

| 条件 | 行为 |
| --- | --- |
| `WEB_TOKEN` 为空/只有空白 | 打印原因，`exit 78`；不监听任何端口 |
| `WEB_ALLOW_NO_TOKEN=1` | 允许空 token（仅本机调试；不要和 `WEB_BIND=0.0.0.0` 一起用） |
| token 不匹配 | 401 HTML 说明页（不泄露下游数据） |
| 端口被占用 | 打印 `EADDRINUSE`，主端口致命退出；origin 端口只告警 |

## 3. 路由规则

| 路径 | 行为 |
| --- | --- |
| `/healthz` | 200 `ok`，不鉴权 |
| `/logout` | 清 cookie，302 `/` |
| `/bridge`、`/dsh`、`/napcat` | 308 到 `/bridge/` 等 |
| `/`、`/index.html` | 导航页；不鉴权、无下游数据 |
| `/_/status` | 并发探活三个下游，返回 `{bridge,dsh,napcat}` 布尔表 |
| `/bridge/...` | 转发到桥接器；`/bridge/` → `/` |
| `/dsh/...` | 转发到 DSH；401 且 `Accept: text/html` 时换说明页 |
| `/napcat/...` | 转发到 NapCat；页面请求自动补 `token=` |
| `/webui...` | 认领 NapCat 的绝对资源路径，转发到 `/napcat/` |
| 其它 | 404 `not found` |

### 3.1 为什么有独立 origin 端口

DSH 与 NapCat 的前端写死绝对路径：`/assets`、`/api/...`、`/webui/assets`。
把它们塞在 `/dsh/`、`/napcat/` 前缀下，资源会落到网关根路径而 404。
所以给各自一个“根路径即下游根”的端口；`/dsh/` 前缀仍然保留给旧书签和探活。

### 3.2 NapCat 的 token 只补页面

NapCat WebUI 自己的 token 与网关 token 是两件事。网关从 `NAPCAT_WEBUI_JSON` 读出 token：

- 只在页面请求上补 `?token=`；
- **不补** `/api/*`：实测 `/api/auth/login?token=...` 会直接 Unauthorized；
- 不把网关的 `tinda` cookie 转给 NapCat：转发前会去掉，保留下游自己的 cookie。

### 3.3 DSH 401

DSH 的网页端只认它启动时打印的授权串，网关替它签不了。对 HTML 请求返回一页说明；
对 `Accept: application/json` 等非 HTML 请求原样透传 401，避免破坏接口调用。

### 3.4 502

下游不可达时：

- 浏览器请求（Accept 含 text/html）→ 502 HTML，带 `prefix → host:port`、错误码和排查命令；
- 其它请求 → 502 纯文本。

## 4. 启动与配置

`bin/run-web.sh` 做这些事，然后 `exec` 网关：

1. 生成/读取 `$DATA/secrets/web.token`（空文件补成 16 字节随机值，0600）
2. 检查证书：不存在、24 小时内过期、SAN 不含 `WEB_LAN_IP` → 重签；旧文件保留 `.old`
3. export `WEB_TOKEN/WEB_BIND/WEB_PORT/WEB_REDIRECT_PORT/WEB_HTTP_PORT`
4. export `WEB_DSH_ORIGIN_PORT/WEB_NAPCAT_ORIGIN_PORT`
5. 从 `BRIDGE_LISTEN` 推导 `BRIDGE_PANEL_PORT`（面板与桥接器同端口）
6. 从 `NAPCAT_WEBUI_JSON` 解析 `NAPCAT_WEBUI_TOKEN`（可选）

完整配置键见 [配置说明.md](配置说明.md) 第 2、4 节。

## 5. 失败模式对照

| 现象 | 原因 | 先看 |
| --- | --- | --- |
| 启动即退出，日志“拒绝启动：WEB_TOKEN 为空” | token 文件空/未生成 | `sh bin/run-web.sh` 重新生成；查 `secrets/web.token` |
| 控制台 401 | cookie 与当前实例 token 不一致 | `doctor.sh` 网关项；`unit.sh restart web` |
| 一直弹 token 输入框 | 浏览器没收到 Set-Cookie（Secure/HTTPS/域名） | Network 看 `set-cookie`；用 `?k=` 重新进一次 |
| `/bridge/` 502 | 桥接器没起，或网关推导的面板端口不对 | `unit.sh status bridge`、`logs bridge` |
| 桥接面板能开但数字不动 | 页面取 `state.json` 被 401/404 | 控制台 Network；`/bridge/state.json` |
| NapCat 面板白屏 | 直接开了 6099，或 origin 端口没开 | 用 8445；查 `WEB_NAPCAT_ORIGIN_PORT` |
| DSH 标签显示说明页 | 设计如此，网关代签不了 | 用 App 的对话界面或 App 打印的授权链接 |
| WebSocket 连不上 | 网关只做 HTTP 转发，不支持 upgrade | 目前 NapCat/DSH 面板走 HTTP；若上游改 WS，需要补 upgrade 转发 |
| 明文端口打开后 token 泄露风险 | `WEB_HTTP_PORT` 调试口 | 用完关掉；默认 0 |

## 6. 安全边界与残余风险

- 对外只有 8443（以及可选的 8444/8445）；都必须带 cookie/token。
- 网关 token 放 HttpOnly cookie，页面脚本读不到；不再进 iframe URL。
- 转发给下游前去掉 `tinda` cookie，避免控制台 token 被 NapCat/DSH 页面拿到。
- `?k=` 仍会出现在首次请求的地址栏/服务端访问日志里；页面会尽快 replaceState，
  但不能保证浏览器/代理没记过。高敏感环境应改用“先登录再导航”的 POST 流程（未实现）。
- 自签证书需要设备信任；`WEB_HTTP_PORT` 是逃生口，不是常态。
- 没有 CSRF token：写操作都在下游自己的鉴权后面；桥接面板本身只读，所以风险有限。
- 网关不限制请求体大小/速率；下游自己处理。对外暴露时应加反代/限流。

## 7. 测试

`units/web/test-gateway.mjs`（16 项，假下游、临时端口）：

- 网关启动、`/healthz`
- `/` 不鉴权且不含 token
- 未授权 `/bridge/` 401
- `?k=` 可换 HttpOnly cookie；`/logout` 清 cookie
- `/bridge/` 反代 HTML；转发时去掉 `tinda` cookie
- `/bridge/panel/state.json` 可用
- `/bridge` 308 补斜杠
- DSH 401 对 HTML 换说明页、对 JSON 原样透传
- 独立 origin 端口可用
- 空 token 启动返回 78

```sh
cd /root/workspace/tinda-bot
node units/web/test-gateway.mjs
```

## 8. 改代码时的检查清单

1. 新路由必须在第 3 节登记
2. 新配置键必须进 `etc/tinda.conf.example`、[配置说明.md](配置说明.md)、CHANGELOG，并在面板/文档可见
3. 改鉴权必须同时改 `test-gateway` 与 [安全模型.md](安全模型.md)
4. 不要把 token 写进 HTML、iframe URL、下游 cookie 或日志
5. 改端口必须同步 `bin/run-web.sh`、`doctor.sh`、[配置说明.md](配置说明.md) 端口表
