# 配置说明（当前实现）

> 只写现在真的存在的配置。旧项目那套 `config.json`（`onebot` / `policy` / `behavior` /
> `groupContext` / `relay` …）已经不存在了，那些记录在 `docs/历史-变更记录.md`。
> 这篇讲的配置，全部可以从 `bin/*.sh` 里 `conf_get` 的键和 `run-*.sh` 导出的环境变量反查出来。
> 最后核对时间：2026-11-15。

## 1. 两套配置，别混

| 层 | 位置 | 谁读 | 内容 |
| --- | --- | --- | --- |
| 模块级 | `$DATA/etc/tinda.conf`（0600，不入库） | 所有 `bin/*.sh` | 端口、监听地址、后端选择、超时 |
| 桥接器进程 | `bin/run-bridge.sh` 装配的环境变量 | `units/bridge/bridge.mjs` | 由上面那份配置翻译而来 |

`$DATA` 的判定：`/data/adb/tinda-bot` 存在就是 Magisk 形态；否则退到仓库内的 `.runtime/`（当前是这种）。

首次运行任一 `bin/*.sh` 会把 `etc/tinda.conf.example` 复制成 `$DATA/etc/tinda.conf`，
之后改那一份；example 只是模板。升级后旧配置缺新键时，`ensure_dirs` 会从 example **补缺**，
不覆盖已有值、也不删旧键；旧键会被 `doctor.sh` 列为「未知配置键」，按清单手工清。

| `BRIDGE_TIMEOUT_MS` | 180000 | 单轮最长等待 |
| `BRIDGE_PERMISSION_MODE` | 空 | 透传给 `dsh headless --permission-mode`；空 = profile 默认 |
| `NAPCAT_API` | `http://127.0.0.1:3001` | 回发消息用的 OneBot HTTP API 根地址 |

| `NAPCAT_WEBUI_JSON` | `/opt/napcat/config/webui.json` | 网关从这里读 NapCat 自己的 token，自动带给面板 |
| `DSH_NODE` | 模块内 node | 拉起 DSH 用的 node |
| `DSH_BIN` | `/opt/dsh/node_modules/@deepseek-ai/dsh/lib/bin.js` | DSH 入口 |
| `DSH_HOME` | `/root/.dsh` | DSH 配置、凭据、会话目录 |
| `WEB_BIND` | `0.0.0.0` | 网关监听地址；`127.0.0.1` = 只本机 |
| `WEB_PORT` | 8443 | HTTPS 控制台端口 |
| `WEB_REDIRECT_PORT` | 8088 | 明文 301 跳转端口；0 = 关 |
| `WEB_LAN_IP` | `192.168.1.3` | 自签证书 SAN 里的局域网地址 |
| `WEB_DSH_ORIGIN_PORT` | 8444 | DSH 面板的根路径端口；0 = 不开 |
| `WEB_NAPCAT_ORIGIN_PORT` | 8445 | NapCat 面板的根路径端口；0 = 不开 |
| `WEB_HTTP_PORT` | 0 | 明文直连端口，只在证书装不进信任库时临时开 |

资源与重试类的键都有区间校验：手改坏了会退回默认值，不会让桥接器起不来；
但 `doctor.sh` 只核对「进程实际拿到的值」，所以改完必须重启对应单元才生效。

本仓库**零第三方依赖**：`bin/check-deps.sh` 只允许 `node:` 内置模块与相对路径，
一旦出现 `node_modules`、`package.json` 的 `dependencies`，或裸模块名 import，门禁直接失败。
这条约束替代了 lockfile + `npm audit`：没有依赖，就没有供应链可审计。

桥接面板没有独立端口键：它和桥接器共用 `BRIDGE_LISTEN` 的端口。`run-web.sh` 从
`BRIDGE_LISTEN` 推导出网关内部变量 `BRIDGE_PANEL_PORT`，所以改监听端口只需要改一处。

## 4. 网关卡用的环境变量

`bin/run-web.sh` 负责准备 token 与自签证书，再 `exec` `units/web/gateway.mjs`：

| 变量 | 来源 | 说明 |
| --- | --- | --- |
| `WEB_TOKEN` | `$DATA/secrets/web.token`（没有或为空就生成 32 位十六进制） | 控制台 token；`?k=` 命中后种 **HttpOnly** cookie `tinda` |
| `WEB_TLS_CERT` / `WEB_TLS_KEY` | `$DATA/secrets/tls.{crt,key}` | 有就走 HTTPS，没有退回 HTTP；SAN 不覆盖当前 IP 时自动重签 |
| `WEB_PORT` / `WEB_BIND` / `WEB_REDIRECT_PORT` / `WEB_HTTP_PORT` | 同名键 | 监听与明文逃生口 |
| `WEB_DSH_ORIGIN_PORT` / `WEB_NAPCAT_ORIGIN_PORT` | 同名键 | 各面板的独立根端口 |
| `BRIDGE_PANEL_PORT` | 从 `BRIDGE_LISTEN` 推导（不是配置键） | 网关 `/bridge/` 的上游端口；改了监听地址会自动跟着 |
| `NAPCAT_WEBUI_TOKEN` | 从 `NAPCAT_WEBUI_JSON` 解析 | 网关用它自己 POST `/api/auth/login`（`sha256(token + ".napcat")`）换 Credential，写进一个引导页让浏览器存进 `localStorage`，再跳回面板。地址栏里不出现 token；凭据 45 分钟内复用，过期后刷新即自愈。换不到就退回 NapCat 自带登录页 |

`WEB_ALLOW_NO_TOKEN=1` 只是本机调试用的逃生口，**不是**配置文件的键；它允许空 token 启动，
不要和 `WEB_BIND=0.0.0.0` 一起用。

## 4.5 回复策略（谁能让机器人开口）

策略在 `units/bridge/policy.mjs`（移植自旧桥接器完整救回的 `src/policy.js`），配置来自
`$DATA/etc/bridge-policy.json`（键 `BRIDGE_POLICY_FILE`，模板 `etc/bridge-policy.example.json`）。

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `privateChat` | `allowlist` / `allow` / `deny` | 私聊：白名单 / 全开（必须显式 `allowAllUsers`）/ 全关 |
| `groupChat` | `mention` / `allow` / `deny` | 群聊：必须 @ / 全接 / 全关 |
| `allowUsers` | QQ 号数组 | 允许私聊的人；**第一个自动成为 owner**，其余是 admin |
| `allowGroups` | 群号数组 | 允许的群；为空且没开 `allowAllGroups` = 所有群都拒绝 |
| `ownerUsers` / `adminUsers` | QQ 号数组 | 命令角色；不写就按 `allowUsers` 顺序推 |
| `allowAllUsers` / `allowAllGroups` | 布尔 | 显式放开；开了会在日志与面板告警 |
| `ignoreSelf` | 布尔（默认 true） | 自己发的消息不处理 |

判定顺序：自己 → 用户白名单 → 群白名单/模式 → 是否 @。**空白名单一律是拒绝，不是放开。**

没有配置文件时用默认策略：`privateChat=allow` + `allowAllUsers=true`（私聊全接）、
`groupChat=mention` + `allowAllGroups=true`（群里必须 @）。这种状态 `hardened=false`，
面板「回复策略」那行标 **未加固**，`doctor.sh` 也会提示。

被拒只记元信息：事件流里是 `策略拒绝：群里没 @ 我`，不含聊天正文。

自测：`node units/bridge/test-policy.mjs`（24 项，纯函数）+
`node units/bridge/test-policy-wire.mjs`（18 项，真起桥接器走一遍）。

## 4.6 拟人化投递（回复像人发的）

`units/bridge/humanize.mjs`：把一条模型回复拆成几条、条间停顿一下。纯函数算计划，
`bridge.mjs` 只负责「照着计划发 + 睡」。

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `BRIDGE_HUMANIZE` | 1 | 0 = 关掉，整条一次发完 |
| `BRIDGE_HUMANIZE_MAX_BUBBLES` | 3 | 最多分几条 |
| `BRIDGE_HUMANIZE_MAX_CHARS` | 240 | 单条字数上限 |
| `BRIDGE_HUMANIZE_TOTAL_DELAY_MS` | 4000 | 条间停顿总和上限 |

规则：

- 按中文/英文标点断句；**代码围栏整块不拆**（宁可一条长，也不能把 ``` 切开）
- 第 1 条不等待；之后每条按「字数 × 25ms」估打字时间，夹在 350–1800ms，再叠 ±25% 抖动
- 总等待封顶（默认 4s）：超了就砍后面的等待，而不是放弃分条
- 超过条数上限时，剩下的**并进最后一条**（刷屏比一条长更烦）
- 只有模型回复走分条；命令回执仍是一条（`/help` 那种表格拆开就看不懂了）
- 发到一半失败：已发的算数，剩下的进补发队列，不重发前面的

自测：`node units/bridge/test-humanize.mjs`（16 项，纯计划）+
`node units/bridge/test-humanize-wire.mjs`（10 项，真起桥接器数分段）。

### 4.6.1 输入状态（「正在输入…」）

`units/bridge/typing.mjs`：一轮回复开始时给私聊发一次 NapCat 的 `set_input_status`
（`event_type=0`），按间隔续期，结束时一定发 `event_type=1` 关掉——成功、失败、提前 return
都会走 `finally`，不会留一个永远在输入的假象。

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `BRIDGE_TYPING` | 1 | 0 = 完全不发 |
| `BRIDGE_TYPING_KEEPALIVE_SEC` | 8 | 续期间隔（0–120）；0 = 只亮一次 |

规则：

- **只在私聊发**：NapCat 只实现了 C2C 的输入状态，群聊发了没有任何效果，所以直接跳过
- 续期的理由：客户端会自己丢掉过期的输入状态，8 秒刚好在消失前刷新
- 发送失败只记一行 `warn: 输入状态失败`，**绝不影响这一轮回复**
- `user_id` 是纯数字时按 number 发（OneBot 实现里要 number 的居多）

自测：`node units/bridge/test-typing.mjs`（15 项，假定时器）+
`node units/bridge/test-typing-wire.mjs`（9 项，真起桥接器断言发包序列）。

## 4.7 群上下文（被 @ 时知道前面在聊什么）

`units/bridge/group-context.mjs`：每个群一段内存环形缓冲，只留纯文本。

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `BRIDGE_GROUP_CONTEXT` | 1 | 0 = 关掉（不记也不注入） |
| `BRIDGE_GROUP_CONTEXT_MAX` | 8 | 每群留最近几条 |
| `BRIDGE_GROUP_CONTEXT_CHARS` | 1200 | 注入块字数上限 |

规则：

- **没 @ 的群消息也记**——不然被 @ 的时候缓冲是空的，等于没有上下文
- 注入时**排除当前这句**（它本来就在正文里），最多带前 7 条
- 字数不够时**丢最旧的**，保留「刚才在聊什么」
- 每条消息最多留 300 字、每群 8 条、最多 50 个群、2 小时过期
- 注入格式：`[群聊上下文] 最近 N 条…` + `- 昵称(号码后4位): 内容`
- 只在内存里：不落盘、不进日志、面板只显示「几个群 / 几条」，没有正文
- `/context` 看本群缓冲与下一条会注入什么；`/context clear`（admin）清空本群

自测：`node units/bridge/test-group-context.mjs`（15 项，纯结构）+
`node units/bridge/test-group-context-wire.mjs`（11 项，真起桥接器看注入内容）。

## 4.8 输出档位、自动压缩、维护期回复（⑤）

### 输出四档

`units/bridge/output.mjs`。档位**每个聊天一份**，存在 `$DATA/state/bridge/output.json`，
下一轮生效；默认 `minimalist`。

| 档位 | 发什么 |
| --- | --- |
| `minimalist` 极简 | 只发最终总结 |
| `concise` 简洁 | 执行中的正文 + 最终总结 |
| `detailed` 详细 | 工具调用 + 正文 + 总结 |
| `complete` 完整 | 工具调用 + 思维链简要（≤300 字）+ 正文 + 总结 |

`/output` 无参打印当前档位（带 ▸）；`/output <档位>` 切换并回「输出档位已切到：…下一轮生效」。
需要 admin。数据来源是 `dsh headless --json` 的 ndjson：`thinking` / `tool_call` / `tool_result` / `text` / `final`。

### 自动压缩

headless **没有** `/compact`（实测：把它当用户消息，模型只会自己写段摘要）。
所以这里的「压缩」是：同一聊天聊满 `BRIDGE_AUTO_COMPACT_ROUNDS` 轮后，后台再跑一次 DSH：

> 请把这次会话到目前为止的要点压缩成一段不超过 400 字的摘要…

拿到摘要后：存 `$DATA/state/bridge/summaries.json`、**丢掉会话映射**（下一轮开新会话）、
把摘要放在提示词最前面（`[之前会话的摘要] …`）续接。旧会话仍留在 DSH 里，`/sessions` 可查。
默认 15 轮；`0` 关闭。代价：每 15 轮多一次模型调用。

### 维护期自动回复（relay）

`units/bridge/relay.mjs`：DSH 连续失败到 `BRIDGE_RELAY_AFTER` 次后，不再一条条回「出错了」，
统一回 `BRIDGE_RELAY_MESSAGE`；冷却 `BRIDGE_RELAY_COOLDOWN_SEC` 内只回一次（记 suppressed）。
成功一轮即复位。

自测：`test-output.mjs` 14 项 + `test-relay.mjs` 8 项（纯函数）+
`test-output-wire.mjs` 13 项（假 dsh 产出 thinking/tool/text/final，验证四档差异、
档位按聊天隔离、自动压缩落摘要、连续失败进维护期）。

## 4.10 交互动作（表情 / 撤回 / 戳一戳）

`units/bridge/interactions.mjs`：模型在回复正文里写标记，桥接器**先把正文发出去**，再执行动作，
最后把标记从可见文本里删掉。旧版 `src/interactions.js` 已丢失（见 `docs/待恢复清单.md` §1），
这一版是按 `bridge.js` 的调用点与任务书重写的；中文表情 ID 来自本机 QQ 的 `face_config.json`，不是猜的。

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `BRIDGE_INTERACTIONS` | 1 | 总开关；0 = 不解析也不执行，正文里的标记原样保留 |
| `BRIDGE_INTERACTIONS_GROUP_POKE` | 0 | 群里是否允许 `[[poke]]`；0 = 跳过，避免绕过群 mention 策略 |
| `BRIDGE_INTERACTIONS_MAX` | 2 | 每轮最多几个动作（1–5）；多余的丢掉并记 `忽略多余动作` |
| `BRIDGE_INTERACTIONS_TIMEOUT_MS` | 2500 | 动作总时限（100–10000ms）；超时/失败都不影响正文 |

三个标记：

| 标记 | 动作 | OneBot 调用 |
| --- | --- | --- |
| `[[react:赞]]` / `[[react:123]]` | 给用户那条消息加表情 | `set_msg_emoji_like` `{message_id, emoji_id}`，`emoji_id` 是字符串 |
| `[[recall]]` | 撤回**上一轮**已发出的所有气泡（不碰本轮） | `delete_msg` `{message_id}`，逐条删 |
| `[[poke]]` | 戳一戳发消息的人 | 私聊 `friend_poke` `{user_id}`；群 `group_poke` `{group_id, user_id}` |

规则：

- **代码围栏内不解析**：按行扫描，三个反引号围栏里的标记原样显示；跨多行/未闭合围栏都按「围栏内」处理
- **纯动作回复不发空消息**：正文删完为空时不发；动作仍然执行
- **每轮最多 N 个**：按正文出现顺序取前 N 个，多余的从正文删掉但不执行，日志记一行 `忽略多余动作`
- **动作失败不挡正文**：正文先送达，再在总时限内执行动作；失败/超时只记 `warn: 动作执行异常`
- **撤回上一轮**：`sendReply()` 返回 `data.message_id`，每轮发完把本轮 id 存进内存 `lastBubbles`
  （按 chatKey，不落盘；气泡 id 只在 NapCat 会话有效期内可删，重启后陈旧 id 反而会报错）。
  下一轮 `[[recall]]` 只删这份上一轮 id，本轮正文不删。旧版 `emit()` 先动作后正文，recall 天然删上一轮；
  现在正文优先，所以必须显式记住上一轮（P0-1b）
- **没有上一轮**：第一次对话/刚重启时 recall 记 `skipped`，日志 `warn: 没有上一轮气泡可撤回`，不报错
- **纯动作 recall**：没有正文可发时不发空消息，只删上一轮；上一轮本身是纯动作（没气泡）时，下一轮 recall 继续 skipped
- **提示只注入一次**：每个 DSH 会话第一次拼 prompt 时附加一段「能写什么、会被删掉、最多几个、代码块里不生效」；
  用内存 Set 记会话 id，进程重启后重注一次无害；`BRIDGE_INTERACTIONS=0` 时不注入
- 中文名映射：赞=76、爱心=66、笑哭=182、鼓掌=99、疑问=32、捂脸=264；未列出的名字按表情 ID 原样传
- 面板「交互动作」一行只显示开关、最近一轮执行/失败数，不记正文

自测：`node units/bridge/test-interactions.mjs`（58 项纯函数）+
`node units/bridge/test-interactions-wire.mjs`（52 项：假 NapCat + 假 DSH，不连真 QQ；
含两轮 / 连续三轮 / 首次 recall / 纯动作 recall / 删除失败等撤回语义用例）。

## 5. NapCat 侧的配置（不在本仓库里，但由脚本写）

`bin/napcat-wire-onebot.sh` 改 `/opt/napcat/config/onebot11_<uin>.json`：

```jsonc
{
  "network": {
    "httpServers": [{            // 桥接器 → NapCat（回发消息）
      "name": "tinda-api", "enable": true, "host": "127.0.0.1", "port": 3001,
      "messagePostFormat": "array", "token": "<secrets/napcat.token>"
    }],
    "httpClients": [{            // NapCat → 桥接器（推事件）
      "name": "tinda-bridge", "enable": true, "url": "http://127.0.0.1:6700/",
      "messagePostFormat": "array"
    }]
  }
}
```

改完必须重启 NapCat 才生效（它不监听这个文件）。

`/opt/napcat/config/webui.json` 里的 `token` 是 WebUI 自己的口令，网关读它并自动带进面板；
它的登录是 `POST /api/auth/login`，body 为 `{ "hash": sha256(token + ".napcat") }`。

长跑期间不会自动切割。

## 8. headless profile（本机专属）

桥接器用 `dsh headless` 跑每一轮。上游的 headless profile 默认**关掉**交互式凭据库和账号插件
（`dsh-headless/cordis.patch.yml` 里 `credentials` / `authorization` / `deepseek-account` 都是 `disabled: true`），
理由是「一次性任务应该用启动时给的 API key」。这台机器只有 App 的账号登录态，没有 API key，
所以 `$DSH_HOME/profiles/headless/cordis.patch.yml` 覆盖成：

```yaml
- id: agent-default-model
  name: "@deepseek-ai/dsh-agent-default-model"
  config:
    provider: deepseek-account
    model: deepseek-flash
    reasoningEffort: high
- id: credentials
  disabled: false
- id: authorization
  disabled: false
- id: deepseek-account
  disabled: false
```

判据：`dsh --profile headless --json -` 能回话，且不再报 `MISSING_CREDENTIAL` /
`ACCOUNT_SIGN_IN_REQUIRED`。
