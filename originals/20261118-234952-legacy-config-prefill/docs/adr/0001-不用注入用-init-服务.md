# ADR-0001：不用注入，改用 Magisk init 服务

## 背景
需求是「开机自启、杀不掉、在 root 域跑」。最初设想是注入系统进程（Zygisk / 寄生）。

## 可选方案
1. Zygisk / ptrace 注入 system_server 或系统应用
2. Magisk 模块 + init 服务（service.sh → supervisor）
3. 什么都不做，继续用 Termux / proot

## 决定
选 2。

## 理由
- Node 运行时塞不进 system_server（没有 libnode，也起不了完整 V8 环境），注入只能承载 Java/native 薄层，跑不了桥接器
- 三个目标（开机自启、抗杀、root 权限）init 服务全都能给，注入不多给一分权限
- 注入是 ACE 这类反作弊的重点目标（maps / preload / ptrace），而设备上还要玩三角洲
- 实测：/data/adb/modules 存在本身不触发封禁（现有模块与游戏共存）

## 代价与残余风险
- 新增暴露面：一个 root 进程、一个模块目录。压到最小：Unix socket、无 TCP 端口、日志进 /data/adb
- 不隐藏自己，也不打算隐藏

## 何时重审
出现「必须借系统进程权限」的硬需求，或 ACE 开始按进程扫描。
