# 0015 用规格里的热安装，别自己搬目录

## 背景

之前的痛点是「装完新版没生效」：管理器把新文件放进 `/data/adb/modules_update/<id>`，
要下次开机才搬到 `/data/adb/modules/<id>`，这中间点「操作」跑的还是旧代码。为此我们在
`customize.sh` 里自己 `cp -a` 把新代码同步进运行目录（v0.4.9 起），属于**非规格**做法：
它和管理器自己的搬迁语义重复，遇到管理器标记 remove/disable 或 SELinux 上下文不同就会出错。

## 规格原文（KernelSU / SukiSU 模块文档 · Hot install）

- `customize.sh` 里 `export MODULE_HOT_INSTALL_REQUEST=true` 表示「这个模块可以立即生效」；
- `export MODULE_HOT_RUN_SCRIPT=hotinstall.sh`（相对模块根）指定安装器跑完后要执行的脚本；
- 管理器随后把 `modules_update/<id>` 换成 `modules/<id>`，并以 boot 脚本同样的方式执行
  该脚本：全局 mount namespace、cwd=脚本目录、stdin=/dev/null、忽略 SIGPIPE、
  **最多等 30 秒**，长期服务要在后台起；
- 立刻生效的是：模块文件、WebUI、`action.sh`、`module.prop`；
  下次开机才生效的是：`system/`、`system.prop`、`initrc`、`service.sh` 等；
- **旧版本不会帮你停**；文档明确要求「有守护进程的模块，`MODULE_HOT_RUN_SCRIPT` 要先停旧
  再起新」；
- 能力探测：`KSU_HAS_HOT_INSTALL`。

## 决定

1. `customize.sh`：`KSU_HAS_HOT_INSTALL=true` 时请求热安装并指定 `hotinstall.sh`；
   否则退回旧的「自己同步运行目录」做法（兼容老管理器）。
2. 新增 `hotinstall.sh`：`unit.sh stop web` → 后台 `unit.sh start web` → 打印版本。
   既满足「先停旧」，也不会让安装器等过 30 秒。
3. 门禁 `check-module.sh` 增加三项检查（文件存在、可执行位、customize.sh 里两个变量），
   防止以后又被改回非规格做法。

## 代价与残余风险

- 热安装不改 `service.sh` 的生效时机，开机仍是新版本（本来就是这样，无影响）。
- 管理器不支持热安装时仍走旧路径：行为与 v0.4.9~v0.5.5 相同。
- 停旧实例依赖 `do_stop` 能杀掉卡死的 proot 树；杀不掉会明确记 error。

## 何时重审

- 规格把 `MODULE_HOT_RUN_SCRIPT` 改名或改成变量 `boolean` 语义时；
- 模块开始需要修改 `system/` 时（那样就不能热安装）。
