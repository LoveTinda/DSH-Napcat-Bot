# ADR-0004：改用仓库内 .git + 手动提交，废弃 DATA/repo.git 自动提交

## 背景

ADR-0002 设计的是「`/data/adb/tinda-bot/repo.git` bare 仓库 + `autocommit.sh` 每 5 秒自动提交」。
实际落地变成了仓库自带 `.git`、人工按单元提交、发版后整目录备份到 `/sdcard/backup/`。
旧方案的两个脚本（`setup-git.sh`、`autocommit.sh`）已经无法工作：它们指向已删除的
`app/`，且 bare 仓库不在当前工作树里，`git log` 看不到自动提交。继续留着会让接手人
以为「有自动留痕」，实际没有。

## 可选方案

1. **保留 bare 仓库 + 自动提交**：需要修复两条脚本、把工作树从 `app/` 改到 `units/`，
   还要处理运行中改文件与提交的竞态；收益是无人值守也有记录。
2. **仓库内 `.git` + 人工提交**（采用）：与 GitHub 远端一致，`git log` 就是审计链；
   改动前跑 `bin/snapshot.sh`，发版后跑 `bin/backup-to-sdcard.sh`。
3. **什么都不做**：保留失效脚本，等于把「可追溯」写成口号。

## 决定

选 2。删除 `bin/setup-git.sh`、`bin/autocommit.sh`、`bin/run-bot.sh`（最后一个指向已删除的
`app/src/index.js`），把「先快照、后改、再提交、发版备份」写进 AGENTS.md 与 RUNBOOK.md。
`bin/snapshot.sh` 修成全项目快照（含 `bin/`、`units/`、`contracts/`），不再只备份 `app/docs/etc`。

## 代价与残余风险

- 依赖人记得提交；漏提交的改动至少还在工作树和 `originals/` 快照里，但不会自动进历史。
- pre-commit 钩子不在 git 里，换机器要重新安装；当前用三道检查脚本 + 测试兜底。
- 没有「每 5 秒自动 commit」的细粒度历史；换来的是可读的提交信息和可推送的远端。

## 何时该重审

出现「无人值守的自动改动」需求（例如模型自己改配置并需要逐次留痕）时，重新评估方案 1，
但必须先解决「提交与运行中写入的竞态」和「bare 仓库如何被工作树使用」两个问题。
