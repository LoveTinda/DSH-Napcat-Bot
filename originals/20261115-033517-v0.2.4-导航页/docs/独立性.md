# 独立性（硬性要求）

> 抽象模块之间必须独立；Android 的特殊性允许定制，但定制只能发生在**单元内部**。

## 独立的五个维度（全部必须满足）

| 维度 | 含义 | 违反的样子 |
| --- | --- | --- |
| 1 契约 | 只通过 `contracts/` 说话 | A 直接 import B 的内部函数 |
| 2 状态 | 各自状态目录，互不读写 | A 打开 B 的 `sessions.json` |
| 3 生命周期 | 各自 PID、各自启停、各自退避 | 停 A 时顺手 kill 了 B |
| 4 失败域 | A 崩了 B 不受影响 | 一个进程里跑两套逻辑 |
| 5 版本 | 可单独替换/回滚 | 改 B 必须重装 A |

## 允许的定制（Android 现实）

- 单元内部可以为本机写特化实现（路径、SELinux 域、chroot、省电策略）
- 特化必须放在**本单元目录**或 `local/`，并在文件头写清 `// overrides: <契约>` + 原因
- 特化**不得**改变契约签名、不得读别的单元的状态

## 禁止

- 跨单元读状态/日志/PID
- 单元之间共享全局变量、共享进程
- 用“启动顺序”制造隐式依赖（依赖只能通过契约上报的重连状态体现）
- 把 A 的配置塞进 B 的配置文件

## 强制手段

- 每个单元一个 `units/<name>/unit.conf`（声明类型、入口、PID、日志、状态目录）
- 统一由 `bin/unit.sh` 管理，禁止单元自己写一套守护
- `bin/check-independence.sh` 检查：必需字段齐全、无跨单元路径引用、无跨单元 import
