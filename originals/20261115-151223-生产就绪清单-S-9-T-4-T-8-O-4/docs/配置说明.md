# 配置说明（当前实现）

> 只写现在真的存在的配置。旧项目那套 `config.json`（`onebot` / `policy` / `behavior` /
> `groupContext` / `relay` …）已经不存在了，那些记录在 `docs/历史-变更记录.md`。
> 这篇讲的配置，全部可以从 `bin/*.sh` 里 `conf_get` 的键和 `run-*.sh` 导出的环境变量反查出来。
> 最后核对时间：2026-11-15。

## 1. 两套配置，别混

| 层 | 位置 | 谁读 | 内容 |
| --- | --- | --- | --- |
| 模块级 | `$DATA/etc/tinda.conf`（0600，不入库） | 所有 `bin/*.sh` | 端口、监听地址、后端选择、超时 |
| 桥接器进程 | `bin/run-bridge.sh` 装配的环境变量 | `units/bridge/bridge.mjs` | 由上面那份配置翻译而来 |

`$DATA` 的判定：`/data/adb/tinda-bot` 存在就是 Magisk 形态；否则退到仓库内的 `.runtime/`（当前是这种）。

首次运行任一 `bin/*.sh` 会把 `etc/tinda.conf.example` 复制成 `$DATA/etc/tinda.conf`，
之后改那一份；example 只是模板。升级后旧配置缺新键时，`ensure_dirs` 会从 example **补缺**，
不覆盖已有值、也不删旧键；旧键会被 `doctor.sh` 列为「未知配置键」，按清单手工清。

## 2. 模块级键

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `LOG_MAX_MB` | 50 | supervisor 日志轮转阈值 |
| `RESTART_BACKOFF_MAX` | 60 | 单元重启退避上限（秒） |
| `BRIDGE_LISTEN` | `127.0.0.1:6700` | OneBot 11 事件入口；NapCat 的 httpClients 往这里推 |
| `BRIDGE_BACKEND` | `headless` | `headless` = 每轮 spawn 一次 `dsh headless`；`echo` = 自测回显 |
| `BRIDGE_ALLOW_GROUP` | 1 | 是否处理群消息；0 = 只听私聊 |
| `BRIDGE_TIMEOUT_MS` | 180000 | 单轮最长等待 |
| `BRIDGE_PERMISSION_MODE` | 空 | 透传给 `dsh headless --permission-mode`；空 = profile 默认 |
| `NAPCAT_API` | `http://127.0.0.1:3001` | 回发消息用的 OneBot HTTP API 根地址 |
| `NAPCAT_HTTP_PORT` | 3001 | `napcat-wire-onebot.sh` 给 NapCat 开 HTTP API 用的端口 |
| `NAPCAT_WEBUI_JSON` | `/opt/napcat/config/webui.json` | 网关从这里读 NapCat 自己的 token，自动带给面板 |
| `DSH_NODE` | 模块内 node | 拉起 DSH 用的 node |
| `DSH_BIN` | `/opt/dsh/node_modules/@deepseek-ai/dsh/lib/bin.js` | DSH 入口 |
| `DSH_HOME` | `/root/.dsh` | DSH 配置、凭据、会话目录 |
| `WEB_BIND` | `0.0.0.0` | 网关监听地址；`127.0.0.1` = 只本机 |
| `WEB_PORT` | 8443 | HTTPS 控制台端口 |
| `WEB_REDIRECT_PORT` | 8088 | 明文 301 跳转端口；0 = 关 |
| `WEB_LAN_IP` | `192.168.1.3` | 自签证书 SAN 里的局域网地址 |
| `WEB_DSH_ORIGIN_PORT` | 8444 | DSH 面板的根路径端口；0 = 不开 |
| `WEB_NAPCAT_ORIGIN_PORT` | 8445 | NapCat 面板的根路径端口；0 = 不开 |
| `WEB_HTTP_PORT` | 0 | 明文直连端口，只在证书装不进信任库时临时开 |

桥接面板没有独立端口键：它和桥接器共用 `BRIDGE_LISTEN` 的端口。`run-web.sh` 从
`BRIDGE_LISTEN` 推导出网关内部变量 `BRIDGE_PANEL_PORT`，所以改监听端口只需要改一处。

## 3. 桥接器用的环境变量

`bin/run-bridge.sh` 把第 2 节的键翻译成这些变量后 `exec` 桥接器：

| 变量 | 来自 | 说明 |
| --- | --- | --- |
| `BRIDGE_LISTEN` / `BRIDGE_BACKEND` / `BRIDGE_ALLOW_GROUP` / `BRIDGE_TIMEOUT_MS` / `BRIDGE_PERMISSION_MODE` | 同名键 | 原样透传 |
| `NAPCAT_API` | 同名键 | 回发地址 |
| `NAPCAT_TOKEN` | `$DATA/secrets/napcat.token` | 回发时 `Authorization: Bearer`，不写进命令行 |
| `BRIDGE_STATE_FILE` | 固定 `$DATA/state/bridge/sessions.json` | chatKey → DSH 会话 id |
| `DSH_NODE` / `DSH_BIN` / `DSH_HOME` | 同名键 | headless 用 |

## 4. 网关卡用的环境变量

`bin/run-web.sh` 负责准备 token 与自签证书，再 `exec` `units/web/gateway.mjs`：

| 变量 | 来源 | 说明 |
| --- | --- | --- |
| `WEB_TOKEN` | `$DATA/secrets/web.token`（没有或为空就生成 32 位十六进制） | 控制台 token；`?k=` 命中后种 **HttpOnly** cookie `tinda` |
| `WEB_TLS_CERT` / `WEB_TLS_KEY` | `$DATA/secrets/tls.{crt,key}` | 有就走 HTTPS，没有退回 HTTP；SAN 不覆盖当前 IP 时自动重签 |
| `WEB_PORT` / `WEB_BIND` / `WEB_REDIRECT_PORT` / `WEB_HTTP_PORT` | 同名键 | 监听与明文逃生口 |
| `WEB_DSH_ORIGIN_PORT` / `WEB_NAPCAT_ORIGIN_PORT` | 同名键 | 各面板的独立根端口 |
| `BRIDGE_PANEL_PORT` | 从 `BRIDGE_LISTEN` 推导（不是配置键） | 网关 `/bridge/` 的上游端口；改了监听地址会自动跟着 |
| `NAPCAT_WEBUI_TOKEN` | 从 `NAPCAT_WEBUI_JSON` 解析 | 只补给 NapCat 的**页面**请求，不补 `/api/*` |

`WEB_ALLOW_NO_TOKEN=1` 只是本机调试用的逃生口，**不是**配置文件的键；它允许空 token 启动，
不要和 `WEB_BIND=0.0.0.0` 一起用。

## 5. NapCat 侧的配置（不在本仓库里，但由脚本写）

`bin/napcat-wire-onebot.sh` 改 `/opt/napcat/config/onebot11_<uin>.json`：

```jsonc
{
  "network": {
    "httpServers": [{            // 桥接器 → NapCat（回发消息）
      "name": "tinda-api", "enable": true, "host": "127.0.0.1", "port": 3001,
      "messagePostFormat": "array", "token": "<secrets/napcat.token>"
    }],
    "httpClients": [{            // NapCat → 桥接器（推事件）
      "name": "tinda-bridge", "enable": true, "url": "http://127.0.0.1:6700/",
      "messagePostFormat": "array"
    }]
  }
}
```

改完必须重启 NapCat 才生效（它不监听这个文件）。

`/opt/napcat/config/webui.json` 里的 `token` 是 WebUI 自己的口令，网关读它并自动带进面板；
它的登录是 `POST /api/auth/login`，body 为 `{ "hash": sha256(token + ".napcat") }`。

## 6. 端口表

| 端口 | 谁在听 | 用途 |
| --- | --- | --- |
| 3001 | NapCat（经 OneBot 插件） | OneBot 11 HTTP API：回发消息、查登录态 |
| 6099 | NapCat | WebUI（被 8445 反代） |
| 6700 | 桥接器 | OneBot 事件入口 + 只读面板（`/panel/`、`/state.json`） |
| 8443 | 网关 | 控制台导航页、`/bridge/`、`/_/status` |
| 8444 | 网关 | DSH 面板（根路径直通 3080；401 时给说明页） |
| 8445 | 网关 | NapCat 面板（根路径直通 6099） |
| 8088 | 网关 | 明文 301 → 8443 |
| 3080 | DSH 自己 | 外部单元，模块只探活 |

## 7. 敏感文件

| 文件 | 权限 | 内容 |
| --- | --- | --- |
| `$DATA/secrets/web.token` | 0600 | 控制台 token |
| `$DATA/secrets/napcat.token` | 0600 | OneBot 回发 token |
| `$DATA/secrets/tls.{crt,key}` | 0600 | 自签证书与私钥 |
| `$DATA/state/bridge/sessions.json` | 0600 | chatKey → DSH 会话 id；**不含聊天正文** |

`supervisor.log` 写入前过 `redact()`：`token=`、`Bearer xxx`、11 位以上数字串打码。
桥接器/网关的日志由 node 直接写，错误摘要里自己调用脱敏；NapCat 的日志是它自己的输出，
不保证没有敏感片段。supervisor 与单元日志在 `unit.sh start` 时按 `LOG_MAX_MB` 轮转一次，
长跑期间不会自动切割。

## 8. headless profile（本机专属）

桥接器用 `dsh headless` 跑每一轮。上游的 headless profile 默认**关掉**交互式凭据库和账号插件
（`dsh-headless/cordis.patch.yml` 里 `credentials` / `authorization` / `deepseek-account` 都是 `disabled: true`），
理由是「一次性任务应该用启动时给的 API key」。这台机器只有 App 的账号登录态，没有 API key，
所以 `$DSH_HOME/profiles/headless/cordis.patch.yml` 覆盖成：

```yaml
- id: agent-default-model
  name: "@deepseek-ai/dsh-agent-default-model"
  config:
    provider: deepseek-account
    model: deepseek-flash
    reasoningEffort: high
- id: credentials
  disabled: false
- id: authorization
  disabled: false
- id: deepseek-account
  disabled: false
```

判据：`dsh --profile headless --json -` 能回话，且不再报 `MISSING_CREDENTIAL` /
`ACCOUNT_SIGN_IN_REQUIRED`。
